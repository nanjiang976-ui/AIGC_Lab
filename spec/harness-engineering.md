# Harness Engineering：影像创作项目管理

版本：1.0 · 建立日期：2026-09-28

## 方法与适配范围

[OpenAI 原文](https://openai.com/index/harness-engineering/) 强调可导航的项目知识、明确约束、可执行检查和反馈。这里将这些原则用于创作资料与生成流程：人确定意图和取舍，AI 按可检查的流程产出，并把失败转化为模板或检查的改进。

下面的目录、状态和验收方式是 AIGC_Lab 的本地设计，不是原文规定的统一标准。

## 一次任务怎样进行

1. **定位**：读取项目地图和目标作品，确认 `scope`、当前版本、已授权动作。
2. **定义**：把需求拆为可检查交付项。缺少影响构图、剧情方向或生成成本的信息时，先标明待确认，继续不依赖它的准备工作。
3. **计划**：小改动写在作品修改记录；多文件或管理规则改动写一份执行计划。保存目标、任务、验收、进展和决定。
4. **制作**：需要叙事时先故事与角色，再脚本、分镜、逐镜头提示词；静态图片走需求、视觉设定、画面行、提示词的短流程。
5. **检查**：运行适用校验，审查叙事和画面约束，修复反馈。自动化不能判定的项目保留人工检查。
6. **交付**：说明交付范围、文件位置、真实检查结果和未执行环节，不以“准备好了”替代生成成功。
7. **沉淀**：将重复出现的问题整理为短规则、模板或测试；任务事实留在作品中，不污染公共库。

已在当前会话明确授权的工作继续执行，无需每阶段重新申请许可。评审是内部质量检查，不应被描述成用户已认可审美结果。

## 状态与门槛

`scope=prompts` 表示文字材料交付；`scope=media` 表示实际生成媒体交付。两者都包含需求、设定、脚本或不适用说明、分镜和提示词。

| status | 含义 | 必须满足 |
|---|---|---|
| DRAFT | 创作中 | 基本结构有效；允许占位和空镜头表 |
| PROMPT_READY | 可发送的提示词已准备 | 必填内容无占位，至少一条完整镜头，发送版对应镜头 ID |
| GENERATED | 媒体生成有记录 | scope=media；提示词门槛通过；generation=PASS 且为当前版本 |
| ACCEPTED | 本轮交付范围通过内容审查 | review=PASS 且为当前版本；scope=media 时还须 generation=PASS |
| ARCHIVED | 暂停使用或历史资料 | 不表示成功；已声明的 PASS 仍须有其版本与证据支撑 |

通常路径：

```text
文字：DRAFT → PROMPT_READY → ACCEPTED
媒体：DRAFT → PROMPT_READY → GENERATED → ACCEPTED
任意阶段可归档；变更内容后回到 DRAFT，再重新检查。
```

校验器只读，不修改状态。不得为让检查通过而虚填审核人、模型、日期或证据。失败原因写入修改记录，`generation.status` / `review.status` 使用 FAIL 或 NOT_RUN。

## 作品契约

从 [完整模板](../01_创作模板/作品模板) 创建真实作品；真实作品全部置于 `04_作品项目/` 的一级作品目录。公共模板和测试夹具不算作品。

- `id`：WORK-001 形式，至少三位数字，项目内唯一。
- `kind`：image / video / comic。
- `scope`：prompts / media。
- `revision`：v001 形式，至少三位数字。
- 固定文件：project.json、00_创作需求.md、01_故事与角色设定.md、02_剧情脚本.md、03_分镜表.csv、04_生成提示词/本次发送.md、06_修改与验收.md。
- 分镜字段：shot_id、duration_seconds、scene_id、character_ids、description、dialogue、image_prompt、video_prompt、reference_files。
- 镜头 ID：EP01_SH001 形式；图片也使用这一编号，单幅图片对应一行。镜头 ID 在作品内唯一。
- 图片时长可为 0；video/comic 每镜头时长须大于 0。这里 comic 指有时间轴的漫剧，静态条漫使用 image。
- character_ids 与 reference_files 多项用英文分号分隔；无人场景/无参考素材可留空，不能编造文件路径。
- 图片不适用的视频提示词可写“不适用”。含叙事的视频不能省去动作和时间变化说明。
- 参考文件与证据使用作品目录内相对路径。公共素材需复制到作品内再引用，同时保留来源。禁止绝对路径、越界路径、符号链接或 Windows 重解析点。

## 证据与版本

generation=PASS 时记录 tool、model、generated_at、revision 和非空 evidence 列表；review=PASS 时记录 reviewer、reviewed_at、revision 和 evidence。时间使用 ISO 格式（如 `2026-09-28T15:30:00+08:00`）。证据文件必须真实存在且非空。

generation.evidence 应指向实际生成资产及生成记录，review.evidence 应指向有检查结论的验收记录。审查人可以是实际执行检查的 Agent 或用户，但必须如实记录身份；不要把 Agent 复查写成用户验收。证据记录包含文件位置、检查项、实际结果与残留问题。

修改已准备/已验收的具体内容时，先保留旧文件或 Git 版本，递增 revision；将 status 改回 DRAFT，把对应 generation/review 重置为 NOT_RUN，并将历史结果移到修改记录中。历史版本可单独归档，不删除历史媒体。

当前校验器校验“声明的版本相符”和证据路径存在，不验证媒体真实性，也不能发现人为遗漏的版本递增。审查时须同时查看 Git 差异、实际提示词和媒体，避免旧结果被误用。

## 检查分层

- **结构检查**：入口文件、必需目录、作品登记、字段类型、镜头编号、引用、文档链接。
- **提示词检查**：必填内容、待确认项、镜头和发送版对应。
- **交付检查**：按 scope 检查生成与审查证据及版本。
- **内容检查**：故事动机、对白、角色/服装/场景一致性、运镜可行性、字幕可读性等，使用 [验收表](acceptance.md) 逐项判断。

运行命令见 [README](../README.md)。默认结构检查也会检查作品已声明的更高状态；显式 prompts/delivery 检查不能在零作品时通过。

## 模型适配与成本

通用创作描述与工具专用参数分离。需要新模型时，先查官方能力与当前输入格式，将日期、来源、未核验项记入适配记录；不要从模板推断任何模型必然支持多图、首尾帧、配音或负向提示词。

媒体生成先用一个代表性镜头验证角色与风格，记录实际花费和问题，再在授权预算内扩展。没有生成授权时只做文字材料。不要安装模型或调用付费服务来“顺手测试”。

## 维护与审查

- 校验器改变：先用反例证明旧行为存在问题，再实现和测试；安排独立 Agent 审查契约及边界。
- 创作修改：按影响范围复查，不因修改了 README 就重生成所有媒体。
- 可复用经验：在任务结束时检查一次，只有跨作品有效才更新模板。未经用户确认不修改第三方/系统 skill；不自动写长期记忆。
- 定期清理的内容是过时规则与重复知识；本项目不设置自动定时任务。无论何时都禁止批量/递归删除。
- 本地 Git 记录文本变更；大媒体独立备份。无远程地址时不声称已云端备份。
