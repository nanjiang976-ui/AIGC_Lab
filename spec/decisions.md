# 决策记录

## ADR-001 · 采用 Harness Engineering 的创作项目适配

- 日期：2026-09-28
- 背景：用户要求整理当前目录并用 “Hermers engineering” 管理。联网检索未确认该拼写对应的独立方法；结合上下文，本次按 Harness Engineering 处理。
- 来源：[OpenAI 原文，2026-02-11](https://openai.com/index/harness-engineering/)，2026-09-28 阅读。
- 决定：短 AGENTS 地图、分层项目知识、执行计划、可执行检查、证据和复盘；不把其他软件产品项目的全部发布流程搬过来。
- 影响：本项目使用自己的创作状态和验收规范，不宣称这些字段是官方标准。

## ADR-002 · 保留 AIGC_Lab 与项目级规则

- 日期：2026-09-28
- 决定：保留当前目录名 AIGC_Lab，显示名为 AI 影像创作实验室；本轮 AGENTS.md 写入当前项目。
- 依据：用户说“此项目”，且要求按此前目录建议落地；不涉及全局规则修改。
- 影响：无需移动或重命名目录，不影响其他项目。

## ADR-003 · 同时支持提示词交付与媒体交付

- 日期：2026-09-28
- 决定：使用 scope=prompts / media；文字交付可在未生成媒体时通过文字审查。
- 原因：项目主要任务包含脚本和提示词，不能强制每次创作都花费资源生成媒体。
- 影响：完成报告必须解释范围。文字 ACCEPTED 不等于媒体生成成功。

## ADR-004 · 本地轻量校验与版本管理

- 日期：2026-09-28
- 决定：Python 标准库只读校验，Git 保存本地文本基线；不安装依赖，不创建远程仓库，不设置自动生成或定时任务。
- 影响：测试夹具保留在已忽略的 .harness-tests/；不自动清理。大媒体默认不入 Git，需另行备份。视觉审查仍由人或具备视觉能力的 Agent 执行。

## ADR-005 · 逐轮共创 Skill 与提示词自动积累

- 日期：2026-09-30。
- 依据：用户要求创建可自动调用的 AIGC Skill，逐轮扩展内容、生成提示词、分类积累通用模块，并明确先做平台通用版。
- 决定：本地用户级 `aigc-creator` 允许隐式调用；每轮默认一个关键问题，用户可要求直接起草。提示词库保存参数化模块与来源/版本，允许未实测模块自动入库；先查重，允许零新增。
- 影响：未实测结构与实测结论严格区分；写入库不需要逐条重复确认。用户当轮不保存/不入库的明确要求优先。没有后台自动生成、定时采集或发布动作。初建时 Skill 只在本机安装目录，后续分发方式见 ADR-007。

## ADR-006 · 连续性使用独立台账，不扩展 CSV 契约

- 日期：2026-09-30。
- 决定：图片系列/视频按需使用 `07_连续性台账.md`，分段视频另使用 `08_分段与衔接.md`；固定母版与当前状态分开，计划与实际分开，片段时长和转场重叠单独计算。
- 影响：现有 project.json 与 CSV 字段保持兼容。平台能力确定后才采用首尾帧等控制；没有真实媒体时，不把文本一致性检查写成 C-03/C-04 PASS。上游变化沿依赖复查后续片段。

## ADR-007 · 将完整 Skill 随仓库分发

- 日期：2026-09-30。
- 依据：用户明确要求将新修改与新建 Skill 推送 GitHub，并说明用法。
- 决定：仓库 `skills/aigc-creator/` 保存完整可安装源文件，用户级目录为运行副本；去掉 Skill 对原电脑用户名/盘符的依赖，使用已打开或用户指定的 AIGC_Lab 根目录。
- 影响：克隆后按使用说明安装，仓库与本机安装副本需显式同步。提示词库和作品模板仍在仓库中，单独安装 Skill 不自动取得整个项目。保留初次本地验收记录的历史语境。

## ADR-008 · 创作任务内的经验读取与回写

- 日期：2026-10-16。
- 依据：用户选择每次创作后积累经验，明确要求落地到 AIGC_Lab，将相关规则写本项目 AGENTS.md，并在 README 说明方法与过程；发现未提交改动后，用户选择继续当前目录并保留已有内容。
- 决定：采用[持续迭代规则](持续迭代.md)与[经验索引](../06_实验与复盘/经验索引.md)，通过现有作品/实验记录串联前置检索、后置反馈、条件验证与下一轮复用。复用现有提示词入库规范，初始索引为空，单一写入者维护。
- 影响：经验状态与模块实测、作品验收状态分开；不保存/不入库仍优先；后续任务采用，不补造旧作品反馈。现有 Skill 已读取项目入口，本轮只改项目规则和模板，不修改 Skill、作品、校验器或全局规则，不启用定时任务。

## ADR-009 · Skill链与项目经验循环共同进入main

- 日期：2026-10-16。
- 依据：用户明确要求将已发布的Skill工作树合并main并推送，同时与main最新未提交的迭代机制保持兼容。
- 决定：在项目AGENTS/README及文档入口整合前置经验检索与后置回写；保留20个Skill源码不变。日常经验沉淀不构成修改Skill资源的授权；词语、电影案例或指令改进先成为待维护提案，明确的维护任务才改源码。
- 影响：不入库覆盖三类公共库，各类状态独立；空经验索引不补造条目。WORK-002及旧试用资料/本地链接保持未提交。具体范围、情景复核与保留性验证见[main合并计划](plans/2026-10-16-main合并与迭代机制整合.md)。

## ADR-010 · 用第一性原理驱动每轮创作的经验循环

- 日期：2026-10-18。
- 依据：用户要求将 README 的第一性原理方法接入本项目 AGENTS 与创作前后流程，每轮执行，检查冲突后校验并推送 main。
- 决定：在 ADR-008 的读取与回写循环上，明确先定义结果、还原事实与约束、找最小瓶颈，再提出假设、检索经验并预定判据；执行后对照基线与保持项，保留反例、限制归因，说明停止及下一轮条件。完整规则维护在 spec/持续迭代.md，AGENTS 作入口，作品现有前后记录与实验模板承接，人工验收 I-01～I-05 检查落实。
- 取舍：不把六步只留在 README，也不扩展 project.json/CSV 或用脚本判断经验效果。新作按需求验证首稿、无缺陷可保持原稿，避免为套流程制造失败、强行升版或新增 EXP；旧作品和历史不追补。
- 影响：已确认创作原则、版本重置、经验/模块/作品状态分离、零新增、不保存/不入库与媒体授权边界沿用；最小修改指影响范围，不降低复杂表达要求。不自动修改 Skill、全局规则、长期记忆或启动后台任务。范围与冲突复核见[接入计划](plans/2026-10-18-第一性原理迭代流程接入.md)。
