# 创作经验的持续迭代

版本：1.0 · 启用日期：2026-10-16。

目标：每次创作的反馈进入可追溯记录，下一次创作主动检索和验证相关经验。由 Codex 在执行任务时落实读取与回写，不是后台常驻任务或模型训练。索引只负责找经验，详细事实仍保留在作品或实验记录中。

## 一、记录放在哪里

| 信息 | 唯一记录位置 |
|---|---|
| 经验 ID、当前版本、问题、适用条件、状态、验证日期、来源与复用去向 | [经验索引](../06_实验与复盘/经验索引.md) |
| 本轮检索、采用的经验版本、用户反馈、实际效果、下一步 | 作品的 06_修改与验收.md；无作品的流程任务写本轮计划或复盘 |
| 假设、比较方案、实际输入输出、反例、经验版本和状态变更依据 | 基于[实验记录模板](../06_实验与复盘/实验记录模板.md)的具体记录，或作品内完整复盘 |
| 可发送的参数化表达与模块版本 | 02_提示词库，遵循[入库规范](../02_提示词库/入库规范.md) |
| 模型能力与专用条件 | 05_工具与模型适配，保留来源、模型/版本与核验日期 |
| 项目流程或模板改动的理由 | [决策记录](decisions.md)及对应执行计划 |

公共索引可链接仓库内作品或实验文件，不能引用仓库外任意路径或凭据。它是知识导航，不替代作品的生成/验收证据；project.json 的 evidence 仍只能引用作品目录内真实文件。

## 二、编号、版本和状态

- 经验使用唯一 ID：EXP-001 起，至少三位数字，使用下一个未占用编号；停用编号不回收。每条经验从 v001 起。
- 写前按“问题、方法、必要输入、适用范围”查重。等价经验补证据或反例，不因换角色、换形容词而新增。
- 同一方法只补日期、使用反馈或证据时保留版本；方法、关键条件或结论实质变化时保留旧记录、升版本，新版本从“候选”开始，不能继承旧版验证结论。本轮使用记录必须同时写 ID + 版本。
- 每条索引行链接到包含该经验详细说明的文件/章节；不能只链接通用模板。详细记录至少写明方法、适用/不适用条件、事实与推断、证据类型、来源版本、执行者和日期。

| 状态 | 进入条件 | 创作时如何使用 |
|---|---|---|
| 候选 | 有明确问题、可复用的改法及来源；效果尚未验证 | 只作为待验证假设。试用须符合本轮范围和已有授权 |
| 已在指定范围验证 | 当前经验版本有实际检查记录、预定判据、结果和证据，且结论支持声明的有限范围 | 条件匹配时采用；在本轮继续记录实际效果 |
| 待复验 | 出现反例、证据缺失、模型/入口变化或已知条件不再匹配，使原结论存疑 | 暂停默认采用，记录触发原因；需要时安排受控复验 |
| 停用 | 有记录的失败或冲突，或已被明确替代，不再推荐使用 | 检索时显示原因及替代条目，不进入发送材料；保留历史 |

常规流转：候选 → 已在指定范围验证 → 待复验 → 已在指定范围验证或停用。候选经失败也可直接停用。停用条目要重新启用时先回候选并写原因，重新验证后才能升级。待复验时如需实质改法，升版本并回候选。

普通的“不适用于本次任务”只记本轮未采用，不自动否定原适用范围。出现真实反例时，先记录并暂停受影响结论，再复验、收窄范围或停用；不能删除反例或仅保留成功输出。

### 验证范围不能混用

- **文本/流程**：可验证字段完整性、冲突消除、交付步骤等；记录具体文件、检查项和结果。即使经验在此范围已验证，关联提示词模块仍为“未实测”。
- **媒体效果**：需要真实工具、模型/版本、日期、输入/参数/参考、输出和实际视觉/播放检查；仅写好提示词不能升级。尽量固定其他条件，一次验证一个问题；保留样本数量、失败样本和限制。
- **用户反馈**：保留原话或准确转述、来源位置、时间和适用范围，不能改写成 Agent 已播放/目视检查。
- **审美偏好**：默认留在本作品。只有用户明确要求以后沿用，才记录为项目偏好，并保留确认来源；这也不证明某提示词在媒体生成中有效。

一次成功只支持所记录的条件与样本。跨作品、跨模型扩大结论需要对应的新证据。最后验证日期是实际执行日期；未执行填“未验证”，不能填建档日期充数。经验状态、模块状态与作品的 DRAFT/ACCEPTED 相互独立，不自动同步升级。

## 三、创作前：检索并选用

1. 读作品需求、当前版本及本轮 `prompts` / `media` 范围，再读经验索引。按作品类型、工具/模型、风格和当前问题筛选，只打开相关来源与模块。
2. 核对经验版本、状态、条件、证据和当前用户要求。最新明确需求优先；经验不能覆盖作品设定。模型未知时只采用不依赖该模型的文本/流程经验。
3. 在本轮内部记录写：检索条件、采用/试用的 ID + 版本、匹配理由、预计改善点和判定方法。没有相关经验写“无匹配经验”；相关但未采用的条目写原因，不抄录整库。
4. 候选或待复验经验只作明确标注的试用。未经已有授权，不为了验证经验调用付费服务或生成媒体。经验编号、复盘内容与未决事项不进入“本次发送”。

## 四、创作后：反馈、复验与回写

在一轮可交付修改结束、收到影响结论的反馈、试验失败或暂停时做短复盘；不要求每条聊天消息都写流水账。中断任务在恢复时补记已发生的事实，未执行仍写未执行。

1. **记录事实**：关联作品/版本/镜头、实际采用的经验版本、用户反馈、证据与已执行检查。每条使用结果填写“有帮助 / 无变化 / 变差 / 未执行”；未使用的条目写“未采用及原因”。只有文字结果时注明文本范围。
2. **分开解释**：写观察到什么、可能原因是什么、下次只改什么、如何判断；原因未证实时保持假设。没有新增经验可以明确“零新增”。
3. **决定去向**：本次剧情留作品；可复用方法查重后进经验索引；表达结构按既有规范入提示词库；模型条件进适配记录。未实测模块允许入库，但不因入库而升级经验或媒体状态。
4. **顺序写入**：先保存来源/实验和版本变更依据，再更新实际变化的模板、模块或适配记录，最后由一个写入者重读并更新经验索引。经验索引有变化时同步其变更记录；纯复用只写作品记录，不重复写公共流水账。
5. **留下下一步**：记录待复验的问题、条件及原因；有下一轮创作行动时写入需求卡“下轮从这里继续”。最终报告说明采用/试用、经验新增/更新/停用数量、证据范围及未执行项。

公共写入中途失败：保留已完成记录并报告未同步项；新条目不标为已验证，既有条目状态不无证升级，下一次先查重并核对来源后补齐。不用虚构路径或检查结果补齐表格。

## 五、维护与授权边界

- “不保存/只读”：不回写任何文件，复盘仅在聊天中；“不入库”：不写公共经验索引、提示词库或模型库，作品内部记录仍按本轮保存要求执行。
- 经验索引由单一写入者更新。其他 Agent 提供发现，不并发修改同一索引或公共模块；写前重新读取最新文件。
- 已验收作品不批量补填本模板。本流程从后续创作任务采用；仅补写内部复盘时明确所指的原版本，不改原审查结论；若改变创作正文或影响交付内容，按 Harness 保留旧版、递增作品版本并重置对应状态。
- 修改公共模块先保留被引用的旧版；模板更新只影响以后使用，不覆盖既有作品。不能靠一条经验自动重写所有作品、全局 AGENTS、Skill 或长期记忆。
- 规则和索引属于本地项目资产；不设置定时任务，不自动发布，不进行批量删除。

## 六、如何检查是否落实

按[持续迭代验收](acceptance.md#持续迭代流程验收)审查，再运行根目录的 `python -X utf8 scripts/validate_project.py`。现有脚本检查结构、字段和文档链接，不自动判断经验状态是否有充分证据，也不证明实际创作改善；需单独核对索引与来源、状态变更依据、本轮采用与回写记录。

初始经验索引允许为空。规则建立与纸面情景演练不能作为真实作品经验入库；第一条经验必须来自实际任务和可追溯记录。
