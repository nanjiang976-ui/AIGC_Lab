# 创作经验的持续迭代

版本：1.3 · 启用日期：2026-10-16 · 第一性原理流程接入：2026-10-18 · 拉片与限定 Skill 维护接入：2026-10-19 · 拉片优化审批补充：2026-10-20。

目标：每次创作的反馈进入可追溯记录，下一次创作主动检索和验证相关经验。由 Codex 在执行任务时落实读取与回写，不是后台常驻任务或模型训练。索引只负责找经验，详细事实仍保留在作品或实验记录中。

每轮按 README 的[第一性原理方法](../README.md#从第一性原理推导每一次改动)执行：定义结果 → 还原事实与约束 → 找最小瓶颈 → 写可检查假设并核对经验 → 最小一轮对照 → 按证据沉淀和停止。下文是执行细则；经验与模板提供有条件的方法，不能替代目标和事实，也不能覆盖用户明确要求或已确认的创作原则。

## 一、记录放在哪里

| 信息 | 唯一记录位置 |
|---|---|
| 经验 ID、当前版本、问题、适用条件、状态、验证日期、来源与复用去向 | [经验索引](../06_实验与复盘/经验索引.md) |
| 本轮目标/约束、事实/假设/未知、瓶颈、改前判据、经验检索、改后对照、停止及下轮条件 | 作品的 06_修改与验收.md；无作品的流程任务写本轮计划或复盘 |
| 假设、比较方案、实际输入输出、反例、经验版本和状态变更依据 | 基于[实验记录模板](../06_实验与复盘/实验记录模板.md)的具体记录，或作品内完整复盘 |
| 可发送的参数化表达与模块版本 | 02_提示词库，遵循[入库规范](../02_提示词库/入库规范.md) |
| 模型能力与专用条件 | 05_工具与模型适配，保留来源、模型/版本与核验日期 |
| 项目流程或模板改动的理由 | [决策记录](decisions.md)及对应执行计划 |
| 公开工程/视频/提示词的原始材料、三层拆解、调度/Clip、复刻结果 | [视频拉片复刻库](../03_参考素材与风格/视频拉片复刻/README.md)，原文单一存放，索引只链接 |
| 本项目自定义 Skill 候选改法、基线、独立行为执行与陌生案例复测 | 本轮维护计划/实验记录；通过下文门槛后更新指定源码，引用原案例与版本 |

公共索引可链接仓库内作品或实验文件，不能引用仓库外任意路径或凭据。它是知识导航，不替代作品的生成/验收证据；project.json 的 evidence 仍只能引用作品目录内真实文件。

## 二、编号、版本和状态

- 经验使用唯一 ID：EXP-001 起，至少三位数字，使用下一个未占用编号；停用编号不回收。每条经验从 v001 起。
- 写前按“问题、方法、必要输入、适用范围”查重。等价经验补证据或反例，不因换角色、换形容词而新增。
- 同一方法只补日期、使用反馈或证据时保留版本；方法、关键条件或结论实质变化时保留旧记录、升版本，新版本从“候选”开始，不能继承旧版验证结论。本轮使用记录必须同时写 ID + 版本。
- 每条索引行链接到包含该经验详细说明的文件/章节；不能只链接通用模板。详细记录至少写明方法、适用/不适用条件、事实与推断、证据类型、来源版本、执行者和日期。

| 状态 | 进入条件 | 创作时如何使用 |
|---|---|---|
| 候选 | 有明确问题、可复用的改法及来源；效果尚未验证 | 只作为待验证假设。试用须符合本轮范围和已有授权 |
| 已在指定范围验证 | 当前经验版本有实际检查记录、预定判据、结果和证据，且结论支持声明的有限范围 | 条件匹配时采用；在本轮继续记录实际效果 |
| 待复验 | 出现反例、证据缺失、模型/入口变化或已知条件不再匹配，使原结论存疑 | 暂停默认采用，记录触发原因；需要时安排受控复验 |
| 停用 | 有记录的失败或冲突，或已被明确替代，不再推荐使用 | 检索时显示原因及替代条目，不进入发送材料；保留历史 |

常规流转：候选 → 已在指定范围验证 → 待复验 → 已在指定范围验证或停用。候选经失败也可直接停用。停用条目要重新启用时先回候选并写原因，重新验证后才能升级。待复验时如需实质改法，升版本并回候选。

普通的“不适用于本次任务”只记本轮未采用，不自动否定原适用范围。出现真实反例时，先记录并暂停受影响结论，再复验、收窄范围或停用；不能删除反例或仅保留成功输出。

### 验证范围不能混用

- **文本/流程**：可验证字段完整性、冲突消除、交付步骤等；记录具体文件、检查项和结果。即使经验在此范围已验证，关联提示词模块仍为“未实测”。
- **媒体效果**：需要真实工具、模型/版本、日期、输入/参数/参考、输出和实际视觉/播放检查；仅写好提示词不能升级。尽量固定其他条件，一次验证一个问题；保留样本数量、失败样本和限制。
- **用户反馈**：保留原话或准确转述、来源位置、时间和适用范围，不能改写成 Agent 已播放/目视检查。
- **审美偏好**：默认留在本作品。只有用户明确要求以后沿用，才记录为项目偏好，并保留确认来源；这也不证明某提示词在媒体生成中有效。

一次成功只支持所记录的条件与样本。跨作品、跨模型扩大结论需要对应的新证据。最后验证日期是实际执行日期；未执行填“未验证”，不能填建档日期充数。经验状态、模块状态与作品的 DRAFT/ACCEPTED 相互独立，不自动同步升级。

## 三、创作前：从目标推导改法，再检索经验

1. **定义结果**：读作品需求、当前版本与本轮 `prompts` / `media` 范围，写明给谁看、希望其理解/感受/行动什么、本轮可检查的交付目标。列出不可改变的主题、设定、时长等约束及已授权动作；已确认、获授权的工作假设和待确认分开，已有资料可引用。
2. **还原事实与约束**：记录直接观察及文件/镜头/版本来源，另列原因假设与未知，核对材料、工具、预算和授权。用户改变目标属于新取舍，不据此宣称旧稿失败；尚未观察到的观众或媒体效果仍是未知。
3. **找最小瓶颈**：指出阻碍本轮目标的具体条件、证据及责任节点，限定受影响的文件、镜头与下游依赖。没有已知缺陷时可保留原稿并检查交付；新作无旧稿时从需求选择本轮要解决的创作问题，不编造失败基线。“最小”指改动范围，不等于删掉复杂场面或降低用户目标；改变已确认核心原则前仍须说明并询问。
4. **形成假设并检索**：有改动时先写“条件 C 下，A 改为 B，预计改善 Z”；新作写首稿方案与预期，无改动写保留理由。再按类型、工具/模型、风格和当前问题查经验索引，只打开相关来源。核对经验版本、状态、条件和证据，记录采用/试用的 ID + 版本、匹配理由与改法；没有相关经验写“无匹配经验”，相关但未采用的条目写原因。经验可帮助修订假设，但保留修订依据，不反过来强造需求。模型未知时只采用不依赖该模型的文本/流程经验。
5. **预定判据与基线**：动笔前在本轮内部记录保存原稿位置/版本、保持项、预计改善、如何区分有帮助/无变化/变差及什么结果会反驳假设、检查范围。新作写“无旧稿”，以预定需求判据检查首稿；无改动写保持原稿及检查依据，不强造 A/B。优先验证一个关键问题；确需多项变化时列出各项，后续不能把全部效果归于一项经验。执行中若需改变目标或判据，保留旧项与改变理由，之后另记对新判据的结果，不能事后改写预期冒充验证成功。

每轮使用[作品记录模板](../01_创作模板/作品模板/06_修改与验收.md)的一组前后记录即可，不要求每条消息或每个节点重复建表；只做单一节点时引用已有输入，保留与本步有关的记录。缺少关键条件时先标明，继续不依赖它的工作；在现有授权内执行，不增设逐步确认。候选或待复验经验只作标注试用，不为验证经验擅自调用付费服务或生成媒体。经验编号、假设和复盘不进入“本次发送”。

## 四、创作后：反馈、复验与回写

在一轮可交付修改结束、收到影响结论的反馈、试验失败或暂停时做短复盘；不要求每条聊天消息都写流水账。中断任务在恢复时补记已发生的事实，未执行仍写未执行。

1. **对照实际结果**：关联作品/版本/镜头、原稿、实际变化、用户反馈及已执行检查，逐项对照改前判据与保持项，保留反例和失败结果；运行适用校验，并在起草后另行内容复核，记录实际审查者、范围和证据。记录本轮改法的“有帮助 / 无变化 / 变差 / 未执行”及证据；未改动写保持原稿和检查结果，新作写首稿是否满足预定判据，不捏造相对改善。实际采用经验另逐条写 ID + 版本与使用效果；未使用写原因。只有文字结果时限定文本范围，不能把文字可检查条件写成观众已学会或媒体已可用。
2. **限制解释与归因**：区分观察和原因假设，说明结果支持、反驳或尚不能判断什么。多项因素同时变化、样本有限或无真实输出时明确归因限制；不能把“符合新目标”倒推成原稿失败。没有新增经验可以明确“零新增”。
3. **决定去向**：本次剧情留作品；可复用方法查重后进经验索引；表达结构按既有规范入提示词库；模型条件进适配记录。未实测模块允许入库，但不因入库而升级经验或媒体状态。
4. **顺序写入**：先保存来源/实验和版本变更依据，再更新实际变化的模板、模块或适配记录，最后由一个写入者重读并更新经验索引。经验索引有变化时同步其变更记录；纯复用只写作品记录，不重复写公共流水账。
5. **决定停止与下一轮**：写明本轮达到目标、保持原稿、假设被反驳需另定改法，或等待指定媒体/用户反馈等停止理由；不为增加迭代次数继续重写。需要后续验证时留下具体动作、判据、所需条件和待确认项，有下一轮创作行动时同步需求卡“下轮从这里继续”。结论超出本轮范围/授权时保留未知或未执行，按授权完成其余工作。最终报告说明采用/试用、经验新增/更新/停用数量、证据范围及未执行项。

公共写入中途失败：保留已完成记录并报告未同步项；新条目不标为已验证，既有条目状态不无证升级，下一次先查重并核对来源后补齐。不用虚构路径或检查结果补齐表格。

## 五、维护与授权边界

- “不保存/只读”：不回写任何文件，复盘仅在聊天中；“不入库”：不写公共经验索引、提示词库或模型库，作品内部记录仍按本轮保存要求执行。
- 经验索引由单一写入者更新。其他 Agent 提供发现，不并发修改同一索引或公共模块；写前重新读取最新文件。
- 已验收作品不批量补填本模板。本流程从后续创作任务采用；仅补写内部复盘时明确所指的原版本，不改原审查结论；若改变创作正文或影响交付内容，按 Harness 保留旧版、递增作品版本并重置对应状态。
- 修改公共模块先保留被引用的旧版；模板更新只影响以后使用，不覆盖既有作品。不能靠一条经验自动重写所有作品、全局 AGENTS 或长期记忆；本项目自定义 Skill 只按下节经用户确认的限定授权维护，其他 Skill 仍需单独授权。
- 规则和索引属于本地项目资产；不设置定时任务，不自动发布，不进行批量删除。

### 拉片候选与本项目 Skill 的维护门槛

2026-10-19用户确认的限定维护授权继续作为验证与范围基础；**2026-10-20用户进一步规定：拉片分析产生的项目优化，必须先读当前项目、列出差异和具体提案，经用户批准后再实施。** 此审批要求优先于此前泛化的自动维护表述。保存案例、满足证据门槛或泛指“继续”不等于批准；对同一具体提案已有明确批准则沿用，不重复申请。

批准后的实施仍须经过实际行为对照与陌生案例复测，才更新本项目仓库内自定义Skill及配套资源；不意味着后台任务、重新训练模型或只看一条成功样本就改规则。用户直接指定的具体改法按已有任务授权执行，不重新包装成待批提案。自然语言入口为 [aigc-shot-study（拉片分析）](../skills/core/aigc-shot-study/SKILL.md) 与 [aigc-iteration（创作复盘）](../skills/core/aigc-iteration/SKILL.md)。

1. **先记录案例**：按原工程、成片、原始提示词的实际可得性做镜头/声画、画布/依赖、提示词三层拆解。遮挡、推测与原文分开；没有视频播放不能声称成片有效。完整原文在案例库单一保存，通用模块仍先参数化和查重。
2. **保留真实基线**：给定真实请求，实际执行现有 Skill 并保存版本、原始输入输出和已观察的问题；新增能力没有旧行为时写缺口，不伪造失败。预先写条件、改法、保持项、改善与反驳判据。
3. **验证候选行为**：在隔离候选版本上独立实际执行，评估者只获得请求、Skill 及必要材料，不灌输预期答案。对实际结果做针对性修订，再用未参与规则编写的不同题材/边界案例复测，保存输出和反例。表格存在、格式通过与作者自评不能代替这些执行证据。
4. **限定源码回写**：门槛通过后保留可定位旧版、变更依据和失败样本，最小更新受影响的本项目自定义 Skill/规则资源，按 skill-creator 及项目套件规则校验。经验、通用提示词、语言库、Skill 行为和媒体结果状态仍独立；文字行为复测不升级媒体效果。
5. **维持边界**：不自动同步用户级/全局安装副本、不发布、不更新长期记忆、不改第三方/系统 Skill。核心创作原则或已确认审美默认改变、维护目录扩大、生成/费用/外部权限扩大时先询问。无独立执行条件、反例未处理或结论仍不确定时留候选，写清继续条件，不硬写规则。

每次维护记录源码与 bundle 版本、改前/改后差异、实际校验、行为证据、证据范围和停止理由；一个写入者维护共享库与索引。候选入库不自动触发维护任务，用户仅要拉片或不保存时按其当前范围停止。详见可随套件安装的[迭代协议](../skills/aigc-creator/references/iteration.md)。

## 六、如何检查是否落实

按[持续迭代验收](acceptance.md#持续迭代流程验收)逐项审查改前依据、改后对照与停止条件，再运行根目录的 `python -X utf8 scripts/validate_project.py`。现有脚本检查结构、字段和文档链接，不自动判断是否遵循第一性原理、经验状态是否有充分证据，也不证明实际创作改善；需单独核对本轮记录、索引与来源、状态变更依据及回写情况。

初始经验索引允许为空。规则建立与纸面情景演练不能作为真实作品经验入库；第一条经验必须来自实际任务和可追溯记录。
