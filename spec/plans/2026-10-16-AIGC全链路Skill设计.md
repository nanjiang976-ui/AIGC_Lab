# AIGC 全链路 Skill 设计

日期：2026-10-16。范围：用户授权创建、训练、分类、文档与本地验证；推送前必须交付预览并等待用户确认。此文件记录本轮用户需求及实施解释，不把 Agent 的文本评审视作用户审美认可。

## 目标与授权

把简要创意或已有完整 PRD 转成各环节可复制的制作资料与图片/视频提示词。首要深度场景为多角色剧情短片/AI 漫剧，同时提供常见类型模块。沿用已有 AIGC_Lab 文件契约、单图短流程、提示词库与三层连续性；不执行付费媒体生成。

用户已要求按上轮建议、顺序与规则持续实施，不在普通任务之间重复询问。用户明确批准独立工作树（2026-10-16）；原目录与其未提交作品资料不改动。现有 3 个相关修改文件（README、aigc-creator/SKILL、continuity）已逐文件复制，起点 e621996，分支 codex/aigc-skill-chain。

用户核心逻辑必须保留：重要内容前置、修饰词汇积累与灵活使用、把简要语言翻译为专业摄影/导演语言、真实电影案例、具体镜头数量和张力设计、复杂场面与表演物理化、可直接发送的提示词、相邻分镜衔接、相机/角色/画面三要素。用户已明确选择限定措辞：最重要的主体、动作和硬约束前置，作为项目编排原则，不保证所有模型按位置赋予更高权重（2026-10-16）。六条共同规则写入项目级 AGENTS.md。

## 架构

- 总控：保留 `skills/aigc-creator/` 名称和入口，保存共享协议与资源，按当前阶段、内容类型和用户范围选择节点。
- 10 个共享节点：prd、script、visual-assets、blocking、storyboard、keyframes、video-prompts、audio、editing、review。源文件置于 `skills/core/aigc-*/`。
- 9 个类型模块：narrative、commercial、explainer、presenter、documentary、music、product-demo、visual-art、montage。源文件置于 `skills/modules/<module>/aigc-<module>/`。各模块具有真实专用规则、路由、例子和验收条件，不复制整套节点。
- `skills/catalog.json` 是安装源路径、唯一名称、依赖和分类的索引。安装时平铺到用户 skill 目录，不把目录嵌套自动发现当作已验证事实。
- 核心 skill 通过总控 `aigc-creator` 的可发现路径读取共享 `references`；总控是必需依赖。不会在每个 skill 中维护一份公共规则副本。
- 总控、模块、节点分别负责“下一步选择”“类型取舍”“当前产物”。先选择一个主模块，可叠加一个必要次模块；不默认把所有 skill 一次读入。

## 交付与接口

每步交付创作结果、干净的可发送正文（仅适用生成节点）和交接摘要。交接字段：作品/版本、主模块、阶段、输入版本、已确认/假设/待定、资产引用、镜头编号、起止状态、三要素、持续时长、下游依赖、审查范围。沿用原分镜 CSV 表头；新增字段放配套 Markdown，不强迫旧作品迁移。

原始截图作为用户提供的素材保留；拆解报告把截图1归为详细镜头条目、截图2归为调度/分镜混合稿、截图3归为静态首帧加动态连续镜头。只提炼结构、选择条件和检查方式，不填造打码信息、作品作者或效果证据。

语言库按主体/动作/表演/构图/光线/材质/节奏分类，说明词语带来的可见变化、适用条件与冲突。电影案例保留来源、可核实内容与推断边界；不凭记忆编造精确时间码或导演意图。模型适配带平台、模型版本、入口和核验日期，不承诺某一语序/时长语法跨模型通用。

## 训练与验收

1. 先保留现有 skill 的独立行为基线（模糊输入、完整剧情链、状态冲突、9类用途），如实记录已有优点与缺口，不人为制造失败。
2. 根据缺口创建节点和模块，再以独立执行者实际使用新 skill；保存输入、输出、评价及修订依据。
3. 以同一短片完成 PRD→资产/脚本→调度→分镜→关键帧→视频→声音/剪辑→审查的文字贯通样例；另做陌生题材和变更依赖测试。
4. 格式、名称、目录、依赖、引用、安装冲突由只读检查/安全安装测试验证；叙事、镜头合理性、可复制性由实际样例审阅。
5. README 含项目目的、分类、主流程 Mermaid、使用入口、衔接、文件位置、安装更新、每个 skill 的打磨方法、准确验证范围。
6. 生成和播放为 NOT_RUN，平台内可接受性与媒体质量待实际试拍；不得以文档/测试通过宣称成片成功。
