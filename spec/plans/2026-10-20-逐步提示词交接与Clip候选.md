# 逐步提示词交接、独立道具与 Clip 格式候选

日期：2026-10-20。状态：DONE（本地审阅阶段完成；用户随后已批准Clip v001固定与合入推送，接续[1.3.0实施及发布](2026-10-20-素材声音与全片脉络发布.md)）。下文保留本阶段当时的范围与结果；文字/流程，不生成媒体。

## 目标与来源

用户在[《修好了》全流程测试聊天](codex://threads/01a15353-0b76-7682-bc47-8dc95927bb79)发现节点衔接、Clip 完整格式和素材称呼问题。本轮明确要求：

1. 想法/需求 → 剧本 → 人物、重要道具与场景参考图提示词 → 完整调度 → Clip 提示词。每步交付后用户可调整，再调用下一节点。
2. 剧情重要或用户点名的道具必须有独立参考图提示词。
3. 保留用户六区块、八项风格信息为候选基础；先优化并展示，用户批准后才能固定新 Clip 格式。
4. 每条 Clip 后说明 LibTV 中多选哪些具体素材、各自作用、生成什么节点。
5. README 提供个人笔记入口，支持日后在 GitHub 编辑保存。

事实：当前基线为 b3bbbeb、套件 1.2.0，独立 `aigc-review` 已停用；媒体由用户在 LibTV 验收，Codex 负责文字自检。实际测试曾把三个 Clip 的六区块压成共享表格，且用“参考A/B/C”代称素材。用户随后明确要求完整素材名称。现行规则已有六区块、身份与衣装分离、实际图像标签核对，不重复建立另一套体系。

未知：本轮没有连接 LibTV 查看具体模型入口、多选数量限制、标签分配、视频参考/延长能力及音频支持。截图和用户说明仅支持画布多选组合的工作方式；不能据此保证任一模型都支持全部输入。

## 改前假设与判据

最小瓶颈是当前总控路线略过剧本、节点完成后的交付边界不够具体，以及“物体角色”未落实为剧情道具逐项交付。

假设：在用户逐步调用节点的条件下，把泛化的继续提示改成“本步交付 + 具体下游输入 + 用户续接口令”，并从剧本提取必需独立道具，预计减少跳步、漏资产和画布名称歧义。

保持：现有角色四格预设、原台词、身份/服装分离、Shot/Clip 区别、原作品和媒体状态、用户媒体验收权、全局安装副本与 LibTV 适配副本。

判据：

- 真实请求的基线问题有原始输入输出；修改后独立执行能在当前节点停止、指出下一入口及实际应带的成果。
- 陌生案例能产出关键道具的独立完整图片正文；不把所有背景陈设都拆成资产。
- 每条 Clip 外的画布说明用完整名称和用途，区分身份/结构/空间参考与真实首帧/视频片段。
- Clip 候选留在审阅文件中，没有提前写入正式固定规则或作为“本次发送”。
- 笔记能由 README 到达，初始不填造用户观点，不自动升级为公共经验或 Skill 规则。

反驳条件：继续要求用户重复粘贴同聊天资料、自动进入未请求的下一节点、关键道具仍被场景图替代、虚构 @Image 标签/视频接续能力，或将候选说成已确认。发生时修订并保留原输出。

经验检索：读 `06_实验与复盘/经验索引.md`；EXP-001 v001 是屏幕文字编辑，当前无匹配经验。此次依据用户实际请求及当前基线，不升级公共 EXP 状态。

## 审批边界与停止条件

第1、2、4、5项按本轮明确要求制作可审阅结果。第3项只交候选，不提前固定模板；用户审核后再执行获准变更。源码完成后先展示结果与真实验证，再按用户确定的范围发布。个人笔记目前为本地文件，推送后才是 GitHub 可编辑入口。

达到本地文字/流程交付目标即暂停实施新格式；媒体生成、播放、模型执行效果及用户对候选的批准均不由静态校验替代。
