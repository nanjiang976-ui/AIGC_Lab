# 作品项目

每部漫剧、短片或图片系列独立成一个作品目录。本目录当前只有说明，没有真实作品或已生成素材。

## 创建作品

1. 复制 `01_创作模板/作品模板/` 到本目录，命名为 `WORK-001_作品名称/`，后续作品递增编号；不要覆盖已有作品。
2. 修改 `project.json` 的 `id`、`title`、`kind` 和 `scope`。`id` 在本目录的真实作品中全局唯一，目录名与 id 保持对应。
3. 填写需求、设定和脚本；按[分镜说明](../01_创作模板/分镜说明.md)补充 CSV，再整理本次发送提示词。
4. 记录实际核对和生成情况，按根目录 `spec/` 的规则进行检查与验收。

也可以直接对 Codex 说：“创建一部新作品，名称为……，形式为……，这次只交付脚本和提示词。”由 Codex 检查现有编号、复制模板并补全已知信息。

## 状态与版本

`kind` 使用 `image`、`video` 或 `comic`；comic 指有时间轴的漫剧，静态条漫使用 image。`scope` 使用 `prompts` 或 `media`。默认从 `revision=v001`、`status=DRAFT` 开始。

| 状态 | 含义 |
|---|---|
| `DRAFT` | 正在完善需求、脚本、分镜或提示词 |
| `PROMPT_READY` | 本版本输入材料已准备，尚不代表实际生成 |
| `GENERATED` | 仅 scope=media 使用；有本版本实际生成结果与可追溯证据，尚需交付审查 |
| `ACCEPTED` | 本版本在声明的交付范围内审查通过 |
| `ARCHIVED` | 作品停止推进并保留资料，不表示此前验收通过 |

`generation` 与 `review` 独立记录，状态各为 `NOT_RUN`、`PASS` 或 `FAIL`。`scope=prompts` 的作品可在提示词审查通过后进入 `ACCEPTED`，此时生成仍可为 `NOT_RUN`，报告中必须注明“提示词交付已验收”。

修改已准备（`PROMPT_READY`）、已生成或已验收的具体内容时，先保留旧文件或 Git 版本，再升版本，状态回到 `DRAFT`，重置生成与审查状态、元数据和证据引用。只有与当前 `revision` 对应的真实证据才能支持当前结论。

分镜参考文件与生成、审查证据均使用作品目录内相对路径，文件必须实际存在且非空；公共素材先复制到作品内并登记来源。禁止绝对路径、越界路径、符号链接或 Windows 重解析点。不使用计划、占位符或不存在的结果冒充完成。

“本次发送”仅包含供生成工具使用的文字；所有管理讨论、备选、参数核验与审查意见写入 `06_修改与验收.md`，不要追加到发送正文。
