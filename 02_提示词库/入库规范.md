# 提示词库入库规范

建立日期：2026-09-30。适用于 `aigc-creator` 的自动积累，也适用于手动整理。

## 什么进入公共库

保存可跨作品复用的画面表达、动作结构、构图、风格约束、连续性办法与修复模板。每次创作中出现有用的新结构，完成抽取与查重后自动保存；用户本轮明确“不入库”“不保存”时遵从。

具体故事、角色名字、客户资料、实际人物信息、作品完整长提示词留在作品目录。公共模块用有明确含义的变量替代实例，不能只把名字换掉就称为通用模块。版权/授权限制随素材保留，不自动上传或发布材料。

首批分类见 [使用索引](分类模块/00_使用索引.md)。原有 [通用骨架](通用提示词模块.md) 保留，作为基础组装框架；不要把它与所有分类模块同时堆入生成输入。

## 每次执行

1. **抽取**：判断本次有哪些“以后换一个故事仍然能用”的表达。没有就零新增。
2. **查重**：查索引和目标分类，按用途、必要输入、动作/构图机制比对；同一用途换同义词、角色或背景不新增。
3. **归类**：优先已有类别；跨类别模块选一个主类别并用标签关联，不复制两份。确有不同用途才新增类别，并更新索引。
4. **写入**：使用下一个未占用 ID；写来源、版本、状态、变量、正文和适用边界。来源作品写作品 ID + revision + shot_id + 相对位置，避免虚构引用。
5. **同步**：更新分类索引的条目与数量，在 [入库日志](入库日志.md) 留下新增或修订记录。纯复用记在作品内部，不给公共日志写无变化流水账。
6. **复核**：重新读取已写内容，核对 ID、版本、链接、变量与状态，最终告诉用户新增/修订/复用情况。

公共库只有一个写入者。并行 Agent 各自处理作品或独立分类；需要写同一分类/索引时交由主 Agent 统一查重和编号，写入前重新读取最新内容，防止覆盖。

## 条目格式

ID 采用 `AIGC-类别代码-三位数字`，类别代码与索引一致，如 `AIGC-STORY-001`。模块 ID 在库中唯一；版本为 `v001` 起。

```markdown
## AIGC-类别代码-编号 · 模块名称

- 版本：v001。
- 适用任务：图片 / 图生视频 / 文生视频 / 文字筹备 / 后期等。
- 标签：便于检索的具体用途。
- 输入变量：各变量含义、是否必填、不适用时删除哪个句子。
- 来源：本地设计，或真实作品 ID、revision、shot_id 与相对路径。
- 建立 / 更新日期：实际日期。
- 验证状态：未实测。
- 输入与结果证据：无（未执行）；有证据则写真实位置和范围。

正文使用独立 text 代码块，包含可以参数化复用的实际表达。

- 限制：依赖的输入能力、容易冲突的模块、失败条件。
```

同一分类文件的版本、来源、日期、验证状态和证据可在顶部共享声明；单条有不同条件时必须覆盖说明。模板允许变量，作品发送正文须全部实例化。

## 版本与证据

| 情况 | 处理 |
|---|---|
| 完全等价 | 复用已有 ID，不新增 |
| 文字小修但用途相同 | 沿用 ID，升版本，写清变化 |
| 修改已被作品引用或有实测证据的正文 | 先保留旧版区块/文件再建立新版本；新版本回到未实测 |
| 本质不同的输入/用途 | 新 ID，记录与已有模块的关系 |
| 失败反馈 | 记录实际模型、输入、结果和失败条件；不删除失败历史 |
| 无平台结果，仅文本复核 | 仍是未实测，可另写“结构与逻辑审查通过” |
| 升级为实测可用 | 必须有实际模型/版本/入口、日期、输入参数、参考与输出文件、检查人、范围及限制 |

用户反馈可以记录为用户反馈，不能写成 Agent 实际播放/目视检查。一次成功不代表跨平台通用或每次有效。模型变更或正文修改后，旧证据不自动继承。

## 使用前组装检查

按当前任务选择最少且充分的模块，展开变量并删去重复。特别检查：固定机位与环绕是否冲突；人物位置与运动方向是否矛盾；光源与时间是否一致；动作是否能在时长内完成；画面文字是否应移到后期；依赖的首尾帧/多参考图是否实际支持。

平台专用参数不混入通用正文。模块管理 ID 和实际参考上传映射保存在内部记录，不以这些编号代替模型需要的主体描述。
