## 选择与组合

1. 先读作品的最新需求和设定。只选对本镜头有作用的模块，不把 60 条整体发送。
2. 区分模块用途：创作规划交给创作助手；画面描述交给图片/视频工具；声音和后期说明交给对应工具或编辑流程。不能把所有模块当成同一种生成输入。
3. 以一个主体、一个主要画面意图为骨架，补充所需角色、空间、镜头、光色和连续性约束。每个维度只保留一套当前要求。
4. 用作品中的固定 ID 查找具体描述。固定 ID 是管理索引，发送时还须展开身份、服装、场景和道具特征；不能假定生成工具认识这些 ID。
5. 替换全部 `{{变量}}`，删除不适用句子，解决冲突，生成作品专属正文。变量未确定时保持内部草稿，不将其标为可发送版本。
6. 工具参数单独填写。这里的“避免”是自然语言约束；只有核验支持后才能放入独立负向提示词字段。首尾帧、多图、局部遮罩、视频延长、音频和口型也均为条件能力。
7. 作品实际发送内容存回该作品的 `04_生成提示词/本次发送.md`。公共库只留可复用结构、来源、版本、证据状态。

单张图片可组合：IMAGE-001 + CHAR-001 + COMP-001 + LIGHT-001。逐镜头视频可组合：MOTION-001 + 相应镜头模块 + CONT-001。此处简称均指带 `AIGC-` 前缀的完整 ID；组合时按实际需求删减，不要求全部选用。

## 不兼容与能力边界

- 同一镜头不能同时要求“机位绝对固定”和“环绕主体”；运镜变化须明确阶段，或拆成两个镜头。
- “保持背景完全相同”和“改变相机位置”通常需要重新明确可变项；视角变化会改变可见面及遮挡关系。
- 一个画面不同时要求正面、侧面、背面。若需要设定板，应明确分格；若工具难以稳定分格，拆成独立图片再排版。
- 画面中“文字必须准确”应转为真实文字后期排版或支持精确文本的工具流程，不能把生成约束当成正确性证据。
- 同一 seed、同一提示词、角色固定 ID 都不构成身份一致性保证。需要参考资产、逐镜头状态记录和结果检查。
- 默认按镜头与剧情节拍拆分长视频；单次可生成的时长是平台限制，不是自然的剧情分段单位。实际分段时长须核验，接口参数不能由模板猜测。

## 后续自动沉淀

每轮创作结束提取跨作品仍有价值的表达：移除作品名、姓名、具体剧情、客户信息、独有造型与本地路径，改为变量；按主用途只归入一个分类，其他用途用 ID 交叉引用。先查重，再决定复用已有条目、记录版本修订或新增下一个空闲编号。

新条目默认“未实测”。将其标为实测可用之前，补齐工具/模型/版本、测试日期、实际输入、结果证据、适用范围与失败条件。一次成功不能升级为跨模型通用结论。失败经验也可归档，但要保留发生条件，不将单次失败写成所有工具的固有限制。
