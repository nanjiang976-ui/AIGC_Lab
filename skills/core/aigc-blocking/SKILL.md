# 场面调度与空间连续性

把人物目的、走位、接触和摄影机路径放在同一空间中；动作复杂时补清因果，不只删减动作。

## 入口与依赖

- 用户明确指定完整 AIGC_Lab 工作区时，验证根目录项目契约及共享文件存在，优先用该根的 `skills/aigc-creator/references`。脱离项目时再从当前包的安装根或 `aigc-creator` 元数据定位同版本总控；缺文件则报告，禁止混用旧全局副本或猜路径。检查当前 Skill 与总控 metadata 的 bundle、bundle_version 相同。
- 读取定位后的 `handoff.md`；混合调度稿或移动机位按需读 `screenshot-analysis.md` 的截图2、3，连续观看设计读 `film-cases.md`。
- 本节点决定真实空间里的行为与可达路径；景别、镜头数和剪辑分配交 `aigc-storyboard`。

## 最小输入与缺项

需要本场动作顺序、主要地标、人物/道具起点、结尾目标及已定限制。
已有实际前段时先读取真实末帧与动作记录；未看到素材只能引用用户报告，未知的手、泪痕和机位不自行补成事实。
缺布局可提出有标签的局部示意方案；若会改变已确认的左右关系或镜头功能，先问一个关键空间问题。

## 两套坐标

| 坐标 | 表达示例 | 不能混为 |
|---|---|---|
| 场景空间 | 北墙有窗，桌西侧是A，桌东侧是B | 画面左/右 |
| 人物身体 | A右手、外套右口袋、脸的左侧 | 观众所见左/右 |
| 当前画面 | 从南向北看，A在左，B在右 | 永久世界坐标 |

先给空间地标和相机观察方向，再写画面位置；移动机位后重新投影。
若用户要求A永远在画面左，而相机要绕到北侧，应明确冲突：改路径或经可见走位换位，不同时承诺两者。
越轴并非永远禁用，但需建立新方向或安排连续可见的跨轴运动，让观众知道关系改变。

## 制作方法

1. 写出初始状态：脚所在区域、站坐、身体朝向、视线、双手、持物、衣装与关键环境状态。
2. 把复杂事件分成触发、行动、接触、结果、反应；明确并行动作和必须等待的动作。
3. 标出角色路径和障碍，检查人物能否绕过桌椅、相机能否通过通道，避免穿墙或瞬移。
4. 摄影机每段记录起点、观察目标、路径、终点；运镜理由须对应新信息或人物关系变化。
5. 逐次登记物件归属和接触：伸手→双方接触→接收者握稳→递出者松手→分离，不能漏掉中间阶段。
6. 给每个节拍计划时长和可用切点；长对白或多次动作先试读/排演估时，再分配镜头。
7. 与真实结果比对。计划坐着而实际站起时，选择承接站姿或明确修复上镜，不能下镜自动坐回。

## 输出

- 空间示意：地标、轴线、相机区域和障碍；ASCII/文字即可，画图不能代替解释。
- 调度表：节拍、角色起止、身体/视线、双手/道具、触发、并行关系、摄影机路径。
- 画面转换说明：移动前后谁在哪边、遮挡如何变、重要动作何时可见。
- 计划与实际差异表，以及仅受影响的下游镜头/关键帧/提示词；放配套 Markdown，不改原 CSV 表头。

## 已填短例

空间：北墙窗户；桌在中央；A在桌西侧，B在东侧；相机在南侧向北拍，画面A左B右。
目标：A将杯子递给B，再移到门边；采用8秒调度草案，实际动作时长尚未排演。

| 节拍 | 人物与物件 | 摄影机 / 可见性 |
|---|---|---|
| 0–2秒 | A右手握杯把，向桌中部递出；B左手离开桌面迎接 | 南侧固定双人中景，杯把在两人之间 |
| 2–4秒 | B左手托杯底、右手握杯身；A确认杯已稳住才松开右手 | 稍横移至东南侧，保持两双手与杯在画面内 |
| 4–6秒 | B双手持杯停住；A空手绕桌南端向西门移动 | 相机止在东南侧，人物路径不穿桌 |
| 6–8秒 | A在门边停步回头，B留桌东侧看A | 相机轻摇向西，B转为右侧后景 |

物件链：A右手独持→双方接触→B双手独持；结束时A双手空，杯不回到桌上。
若实际B提前起身，后续先按站姿复算手部高度与遮挡；是否接受偏差由当前授权决定，不能伪造已确认。

## 验收

- 所有人的位置、身体左右、画面左右能分清；相机移动后重新核对。
- 接触动作和持物链完整，旁观者反应在触发之后，路径与障碍相容。
- 复杂性通过动作层次、可见性和切点控制；没有未经同意删掉核心事件。
- 计划和实际分别记录；未看真实末帧时不把推测布局标为已验证。

## 演练请求

- 正常：“A把热杯交给B后绕桌离开，相机同时侧移；给两人走位和交接动作。”观察接触链与相机路径。
- 边界：“原计划B坐着，但上镜实际站起；镜头只改下一镜，仍想绕拍且A始终画面左。”观察实际状态继承、坐标冲突和局部影响。
