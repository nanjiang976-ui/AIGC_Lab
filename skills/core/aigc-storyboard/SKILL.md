# 分镜与摄影设计

让每个镜头承担明确的观看任务，并把相机、角色/主体、画面三要素与前后衔接写全。

## 入口与依赖

- 用户明确指定完整 AIGC_Lab 工作区时，验证根目录项目契约及共享文件存在，优先用该根的 `skills/aigc-creator/references`。脱离项目时再从当前包的安装根或 `aigc-creator` 元数据定位同版本总控；缺文件则报告，禁止混用旧全局副本或猜路径。检查当前 Skill 与总控 metadata 的 bundle、bundle_version 相同。
- 读取定位后的 `handoff.md`、`prompt-language.md`；详细镜头或混合稿按需读 `screenshot-analysis.md` 的截图1、2，借鉴电影技法读 `film-cases.md`。
- 先消费剧本和调度；已有分镜只改受影响镜头，不强制回到 PRD。

## 最小输入与缺项

需要事件/信息节拍、角色/资产不变量、空间与动作起止、目标成片时长。
没有调度时补最小空间图，不编造已经确认的地标；平台未知可完成设计，但单次生成可行性未验证。
已有实际结果优先核对已知状态；看不到前段时将匹配判断标为待素材检查。

## 制作方法

1. 按“新信息、关键动作、反应、空间重建”判断切换需要，提出具体镜头数和合并/拆开的理由。
2. 分配每镜目的与设计张力，说明情绪递进或停顿；张力数字只作创作标记。
3. 每镜写三要素：相机的景别/高度/方向/运动；主体的动作/表情/对白；画面的层次/位置/光线/信息焦点。
4. 将表演写成可见的诱因与反应；运镜服务于信息变化，固定机位可以承担有力的表演。
5. 按 `prompt-language.md` 的“裁切、身体高度与接触点”检查必见对象、接触点和动作范围；比较实际高度、遮挡与裁切边界。需要观众读出的手/落物须入画，其余已知状态可明确延续在画外；确定冲突在生成前修正，并同步首帧、视频和交接。
6. 写入口、出口与切点：视线、动作阶段、持物、光源和声音如何接；动作可以在切点继续而非每镜重新开始。
7. 试读对白和估算动作，核算净片长；超时先指出具体拥挤节拍，再给合并、增时或分段方案。
8. 区分设计镜头与生成片段：一个连续镜头可由数段生成素材拼接，片段上限不自动变成叙事切镜。

## 文件契约

原 CSV 表头保持：
`shot_id,duration_seconds,scene_id,character_ids,description,dialogue,image_prompt,video_prompt,reference_files`。
三要素可写在 description；张力、调度、入口/出口、切点、生成片段映射放配套 Markdown。
character_ids、reference_files 多项遵循原项目分隔规则；无真实素材不虚填路径。
详细图片/视频正文交对应节点，不以“同上”完成必填内容。

## 已填短例

输入：“18秒，A质问，B解释失败后落泪，不揭示其他剧情；A左B右，B坐着。”
建议3镜：双人关系、指责压力、B反应分别占有观看中心；最后留8秒给解释与情绪停顿。

| 镜头 / 计划时长 / 张力 | 相机 | 角色与声音 | 画面 / 入口→出口 |
|---|---|---|---|
| 1 / 4秒 / 1 | 南侧平视双人中景固定 | A下颌紧绷：“你拿了吗？”B抬眼 | A左站、B右坐，桌面前景；B低头→看A |
| 2 / 6秒 / 3 | 同侧A中近景固定，B肩作右前景 | A略前倾：“只有你碰过。”B画外答：“不是我。” | 绿色厨房虚后景，A看右；手仍搭桌边 |
| 3 / 8秒 / 4 | 同侧B近景轻推，胸口以上入画 | B短吸气：“你为什么不信我？”抿唇，一滴泪滑下，垂眼 | B右侧、左留视线空间，暖窗光持续；抬眼→低头 |

镜1→2：在B看向A后切，保持A看右的视线；镜2→3：B画外否认后切其反应。
镜3的泪痕成为后续可见状态，不能下镜无故消失；固定坐姿是身体状态，不靠画面裁掉腿来假定成立。
对白秒数为计划，实际试读和媒体未执行。三镜合计18秒，当前为硬切、画面重叠0秒。

## 输出

- 明确镜头数、选择理由、总时长与张力变化。
- 逐镜三要素和计划状态；需要时更新原 CSV，同时提供不改表头的配套设计说明。
- 相邻镜头连接表、镜头与生成片段映射、尚未满足的关键帧/声音依赖。
- 图片节点取得静态起点；视频节点取得完整动作与运镜；剪辑节点取得切点和时长意图。

## 验收

- 每镜相机、主体行为、画面俱全，无人物镜头明确记环境/物件变化。
- 数量和秒数有创作依据且合计正确；精确节拍不被说成模型必然命中。
- 相邻镜头因果、方向、动作、光与声音能对上，不要求所有切镜首尾像素一致。
- 复杂场面保持用户核心意图，通过合理拆解而非无条件删除解决。

## 演练请求

- 正常：“把两人吵架、B委屈哭的日常描述设计成18秒分镜，明确镜头数和张力。”观察三要素、理由与衔接。
- 边界：“一个连续镜头需要20秒，但当前工具每段只能10秒；别把它改成两场戏。”观察设计镜头/生成片段区分和实际终帧依赖。
