# aigc-prd（创作需求）

个人调用时可直接用 [提示词模板与使用方法](references/usage.md)：短口令、可复制调用模板和已填示例；这些是发给 Codex 的请求，不是生成模型正文。

每次面向用户交付的最后一段，读取同版本总控 `references/handoff.md` 的“面向用户的结尾衔接”，加粗提示下一节点、携带本轮哪些成果及继续口令；缺项按实际依赖选择补齐或草案续接，当前范围结束则明确停止。

作品素材与成片的观看验收按同版总控 `references/handoff.md` 的“用户媒体验收与反馈”执行：用户在LibTV观看确认，Codex负责文字自检及按反馈修改。

把创意整理为能驱动当前制作阶段的需求；已有完整 PRD 时先校验，不重新访谈。

## 入口与依赖

- 用户明确指定完整 AIGC_Lab 工作区时，验证根目录项目契约及共享文件存在，优先用该根的 `skills/aigc-creator/references`。脱离项目时再从当前包的安装根或 `aigc-creator`（全链路创作总控） 元数据定位同版本总控；缺文件则报告，禁止混用旧全局副本或猜路径。检查当前 Skill 与总控 metadata 的 bundle、bundle_version 相同。
- 读取定位后的 `handoff.md`；模糊想法按需读 `interview.md`，涉及已有作品时读 `project-integration.md`。
- 用户只要检查需求时停在本节点；单张图片不强制增加剧情、对白和视频时长。

## 最小输入与缺项

| 入口 | 已有资料 | 首先处理 |
|---|---|---|
| 完整 PRD | 目标、对象、内容与限制已有清楚描述 | 提取确认项，标记真正矛盾和影响下一步的缺口 |
| 模糊需求 | 一句话、画面、情绪或用途 | 复述已知内容，只问当前最关键的一个问题 |
| 续作或单点修改 | 当前版本、用户新要求 | 定位变化和受影响节点，保留其余确认项 |

缺少平台不妨碍形成通用创作需求；记录平台适配待做。
缺少人物关系会改变故事因果时优先问关系；缺少画幅只影响后续构图时可稍后确认。
每轮一个实质问题，可附两三个具体选项，不用一个句号包装整份问卷。
用户授权直接写时使用清楚标注的工作假设；用户未回答不等于接受。
已确认的人物、服装、故事结局和禁改区域直接复用，不以“专业化”为由重写。

## 制作方法

1. 分开“用户要达成什么”和“画面表现为什么”：宣传转化、解释知识或情绪叙事决定不同主模块。
2. 把类型与表达维度分开，例如剧情 / 写实 / 竖屏；真人、2D、3D 不代替用途分类。
3. 从用户描述提取主体、动作、关系、信息变化、情绪落点、交付范围和硬约束。
4. 对照已有资料找冲突，例如30秒对白读完需45秒、静态单图要求连续动作；说明影响和可选取舍。
5. 分别确定本轮范围 prompts/media 与制作输入路线（参考驱动、纯文生、未定），沿用已有授权。只做文字仍可包含参考资产和首帧图片提示词，不据此选择纯文生；实际出图、上传或费用未执行则如实记录。
6. 生成简洁 PRD，再逐条映射到下一节点：人物外观去资产，行为因果去剧本，输入限制去模型适配。
7. 问题答案回填来源；没有答案的必要决定仍留待确认，非关键未知项可随交接继续。

## 明确输出

- 需求摘要：目的、受众、主类型、媒介/画幅/计划时长、核心内容、情绪或信息落点。
- 固定约束：已定角色与服装、场景、道具、必须发生/不能改变事项、参考用途。
- 交付清单：本轮文件或聊天产物、所需参考资产/首帧/动态正文、是否保存/入库；完整流程不能以外观描述代替已要求的图片提示词，单节点按明确范围裁剪。
- 决策表：已确认、授权工作假设、待确认各自有来源；不把建议写成用户原话。
- 下一节点的必要输入、可保留材料、仍缺的一项关键问题；交接格式采用共享协议。

## 已填短例

输入：“30秒写实姐妹争吵片，A误会B丢戒指，最后从A口袋掉出；人物已定，只做文字，可自行分镜。”

| 字段 | 本次整理 |
|---|---|
| 目的 / 主类型 | 用误解与反转产生情绪，剧情 |
| 时长 / 范围 | 成片计划30秒，prompts |
| 确认内容 | 姐妹关系；戒指最初在A口袋；B受委屈；终点为戒指揭示 |
| 复用输入 | 当前版本人物设定，不另设年龄、脸型和衣服 |
| 工作假设 | “A看到戒指后停住”作为结尾表演，需与原要求对照 |
| 下一步 | aigc-script（剧情脚本） 编排信息节拍，aigc-visual-assets（参考图资产） 检查缺失视角 |

如果人物设定文件已可读，本例无需再问“人物长什么样”；若无权读取，只索取该设定。
若用户只说“两人吵架后哭了”，首问可以是：“你更想写哪一种关系冲突？”附家人误解、恋人忽视、朋友怀疑三个方向；不追加时长、平台和画风问卷。

## 验收

- 完整 PRD 获得缺项/矛盾检查，模糊入口只收到一个当前关键问题。
- 需求、假设、未知可区分；已定角色没有被悄悄改写。
- 下游能够执行当前一步；不要求无关信息齐全后才工作。
- 完成的是需求文字，不据此声明剧本、生成或用户审美验收通过。

## 演练请求

- 正常：“这是完整 PRD：30秒16:9姐妹争吵反转片，人物设定已确认，只做文字，自行选镜头数。请检查能否进入脚本。”观察是否直接体检并复用人物。
- 边界：“我想做两个人吵架，一个人委屈哭了，先帮我问清楚。”观察是否只提出一个有分辨力的问题，不生成已确认角色或整份问卷。
