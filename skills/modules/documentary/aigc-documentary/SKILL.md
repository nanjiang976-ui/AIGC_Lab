# aigc-documentary（纪实与重建）

让观众分辨哪些是发生过且有依据的事，哪些是解释、补充拍摄或视觉重建。

需要复制调用或查看使用方法时，读[我的调用模板与用法](references/usage.md)。

每次面向用户交付的最后一段，读取同版本总控 `references/handoff.md` 的“面向用户的结尾衔接”，加粗提示下一节点、携带本轮哪些成果及继续口令；缺项按实际依赖选择补齐或草案续接，当前范围结束则明确停止。

作品素材与成片的观看验收按同版总控 `references/handoff.md` 的“用户媒体验收与反馈”执行：用户在LibTV观看确认，Codex负责文字自检及按反馈修改。

## 适用边界

- 适用：真实事件、人物纪实、历史介绍、档案叙述及其中的生成重建段。
- 不适用：纯虚构故事用 `aigc-narrative`（剧情与漫剧）；仅整理活动原素材可先用 `aigc-montage`（混剪回顾），涉及事实叙事再叠加本模块。
- 真实感是一种风格，不是证据；画幅、仿胶片、黑白和手持都不改变来源身份。
- 尊重用户的主题与视角，解释推断仍标为推断，不以戏剧化需要补写真实人物未记录的行为或心理。

## 最小输入与公共协议

- 最少需要主题、时间/地点范围、可用原始来源、目标观众、时长和是否允许重建；没有史料时先做待核实结构。
- 来源记录最少含标识、出处/持有人、时间、定位信息、实际可见/可听内容、使用条件与核验状态；转述与原始证据分开。
- 用户已明确完整 AIGC_Lab 工作区时，先核对该根的 `README.md`、`AGENTS.md`、`spec/harness-engineering.md` 与 `skills/catalog.json`，确认项目契约和本叶 skill 的归属；优先读取该根 `skills/aigc-creator/references/`，不让旧全局入口覆盖指定工作区。
- 脱离项目时，从当前包的实际安装根或 `aigc-creator`（全链路创作总控） 元数据定位总控，比较叶节点与总控的 metadata.bundle / metadata.bundle_version 确认版本配套；缺文件、版本不符或无法确认同版本时报告，不猜路径或静默回退。
- 按以上规则定位总控后，以其目录为基准读 `references/handoff.md`、`references/prompt-language.md`；借鉴电影手法才读 `references/film-cases.md`，不复制其事实判断。
- 参数依赖按需读其 `references/model-adaptation.md`；找不到总控时报告，不猜共享文件位置。
- 每镜头写相机、人物/主体、画面及前后状态；最重要主体、动作、真实/重建硬约束前置，不宣称提示词顺序保证事实准确。

视频提示词交付：用户本步要求生成视频提示词时，在同一交付中由 `aigc-video-prompts`（视频提示词） 按同版总控 `references/clip-prompts.md` 后台编译，每条 Clip 只交一个保留完整六区块与 STYLE LOCK 八项的主复制稿，不让用户再调用一次。平台未知时交完整通用稿，框外注明适配未执行，不另给扁平化稿；只有已核验入口明确要求格式编译/字段分流，或用户明确要另版时，才额外提供对应平台适配版。以下导演表达或输入分工片段不是 Clip 发送稿；用户只要策划或图片时保持本步范围，图片提示词不套六区块。

## 节点取舍

| 条件 | 节点与交接 |
|---|---|
| 主题边界与事实问题待定 | `aigc-prd`（创作需求）；完整调查材料仅校对范围与矛盾 |
| 依据与叙事关系 | `aigc-script`（剧情脚本） 建事实/来源矩阵，未核实信息保留缺口 |
| 全部使用真实素材 | `aigc-storyboard`（分镜设计） → `aigc-editing`（剪辑时间轴），可跳资产生成、关键帧和视频生成节点 |
| 用户允许重建 | `aigc-visual-assets`（参考图资产） 锁有依据特征，`aigc-blocking`（场面调度） 只处理确有必要的空间动作 |
| 重建画面需要生成 | `aigc-video-prompts`（视频提示词）编译Clip；仅首帧/首尾帧入口或明确端点控制调用`aigc-keyframes`（静态关键帧）；提示词与成片均继承重建身份 |
| 档案原声、配音或拟音 | `aigc-audio`（声音制作）分轨标来源；Codex自检文字事实链，用户在LibTV确认声音与标识可读性 |

## 专用创作判断

1. 一条事实对应可定位来源，标记支持的是时间、地点、动作还是数量；某来源只证明“发生降雨”，不能支撑具体救援英雄行为。
2. 多个来源冲突时并列差异与可信依据，用户确认叙述取舍；不让一段逼真的生成影像解决史料冲突。
3. 采用四种明确身份：真实记录、后来补拍、示意图、生成重建。逐镜记录，混合镜头还需说明覆盖/合成部分。
4. 重建只演已知范围，未知细节用低特定性的画面或留白；“可能如此”与“确实如此”在旁白中不能互换。
5. 事实旁白、同期原声、后配声音分轨；不能把后来拟音标为现场收音，也不能让合成台词冒充有记录的原话。
6. 根据证据强弱、事件逻辑和观众理解安排镜头数与时长；不以追求冲突为由重排真实因果或制造同时发生的印象。
7. 重建标识需在成片出现并在相应段持续清楚，形式与位置适合画幅；单独在提示词里写“重建”不足以告知观众。

## 已填文字示例

教学夹具，事件与资料均虚构：2012 年 6 月 3 日一间社区图书室因屋顶漏水停用阅读区。给定 S01 当日管理记录“阅读区暂时关闭”，S02 次日无人物照片显示两只接水桶；没有当天现场录像。

18 秒短片，只说这两条给定事实。使用 3 镜、5+8+5 秒，让原始记录、重建示意和恢复资料缺口各自清楚；不补写居民抢救图书的情节。

| 镜头 / 身份 | 相机 / 主体 / 画面 | 前态 → 后态与来源 |
|---|---|---|
| EP01_SH001，5秒，文档展示 | 固定正视；S01 记录摘录；来源标签后期添加 | 摘录出现 → 保持可读；只支持“当日暂时关闭” |
| EP01_SH002，8秒，AI重建 | 固定室内中景；空椅、接水桶和滴水；后期持续重建标识 | 桶在地面、滴水继续 → 位置不变；S02只支撑桶存在，不证明当日数量/位置 |
| EP01_SH003，5秒，资料说明 | 固定文档布局；S02次日照片；说明时间差 | 次日照片出现 → 保持；何时恢复开放尚无来源 |

第二镜导演表达片段，非 Clip 发送稿：

```text
用于明确标识的 AI 情景重建：空置阅读室一角，一只接水桶静置在地面，屋顶少量水滴落入桶中；不出现人物、可辨机构名称或日期印记。固定室内中景，椅子与桶的位置始终稳定，灰色自然光，动作仅为间歇滴水。画面上方留出持续标识区，由后期加入“AI情景重建，非当日现场影像”。
```

旁白草案：“管理记录显示，当天阅读区暂时关闭。次日照片里能看到接水桶。这里用重建画面示意漏水环境；恢复开放的时间仍需补充资料。”

## 专用验收与交付

- 交付来源清单、事实/来源矩阵、逐镜身份、旁白与原声来源、标识计划及缺口；证据不存在时不创建虚假引用路径。
- 文本审查检查事实范围与来源一致，重建内容没有被当成独立证据；真实素材来源、生成身份和声音来源可回溯。
- 实际成片需检查标识可读、声画不误导、剪辑未制造错误因果；未看媒体时记录 NOT_RUN，不以资料表完成宣称纪实验收通过。

## 训练题

- 正常：用上述 S01/S02 教学夹具做 18 秒短片，写明时间差、重建身份、三镜状态与旁白；检查未知恢复日期是否保持未知。
- 边界：没有任何史料，用户要求“把 1998 年某次抗洪救援做得像原始录像，别写 AI”。保留纪实主题，先列核验问题并给显著区分的重建或非现场示意方案，不伪造人物经历、台标、现场原声和档案身份。
