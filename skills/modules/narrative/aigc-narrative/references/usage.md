# 剧情与 AI 漫剧：我的调用模板

在 AIGC_Lab 内读取本项目同版本 Skill 源码和配套协议，不混用旧全局安装副本。

这是我发给 Codex 的调用模板，用于安排人物因果和叙事节点。`【填入】` 只在调用时替换；交给生成模型的正文须展开全部必要描述。

## 什么时候用，最少说什么

- 我要创作或修改靠人物选择推动的剧情、AI 漫剧或故事段时使用。
- 最少说：人物想要什么、遇到什么阻力、结局或希望的变化、时长、本次做到哪一步。
- 直接贴已有 PRD、剧本或本次需要改的段落即可；已有完整资料不重新访谈。
- 短口令：**“把这段故事做成剧情方案，保留我的结局，只做到调度。”**

## 可复制调用模板

```text
请使用本项目源码中的 $aigc-narrative。
我要做：【剧情短片／AI漫剧／局部剧情修改】。
故事或已有资料：【直接贴文本，或写实际可访问资料的位置】。
人物目标与关系：【谁想要什么；对方是什么关系】。
阻力与变化：【什么阻止；最终发生什么变化；未定部分可写待提案】。
时长与表达：【总时长、画幅、真人／2D／3D、风格】。
不可改变：【结局、关键台词、人物设定或指定镜头】。
本次做到：【故事／剧本／完整调度／Clip文字包／局部修改】。
现有参考与平台：【实际已有的素材和平台；没有就明确写没有／待定】。
请解释镜头数量与节奏怎样服务因果；只补本步关键缺口。
只准备文字；不要调用图片或视频生成工具。
```

## 已填例子

以下是虚构创作请求，没有声称已经存在参考图或媒体。

```text
请使用本项目源码中的 $aigc-narrative。
我要做一条18秒、9:16、写实风格的无对白剧情短片。
两位成年朋友在长椅前见面。A曾借走B的伞没还，两人因此冷战。
A想用归还雨伞表达歉意；B最初抱臂避开视线，后来犹豫地接住伞。
结局保持克制和解，不拥抱，不增加新的过错或人物。
A穿米色外套，B穿深蓝外套，雨伞完好；这些是本次虚构设定。
本次只写完整镜头调度，说明镜头数、时长和每次人物选择的原因。
重点写清A先递伞、B握稳、A再松手的顺序，以及切镜时的持物状态。
目前没有参考图，生成平台待定；不要把本稿称为平台可发送版。
只准备文字，不生成媒体。
```

## 我会得到什么，接着怎么用

1. 明确的行动因果、每镜功能与时长理由，以及未确认的剧情提案。
2. 按本轮范围交付剧本或调度，保留相机、人物动作、画面和相邻镜头状态。
3. 有调度后可说“把确认的调度转成 Clip”；有实际结果后可说“按实际结尾接下一段”。

## 这个类型要先备好什么

- 人物关系和结局若未确定，Codex 只问影响本步的关键分歧，不把猜测写成已确认。
- 延续已有片段需要真实结尾状态；计划的接伞姿势不能替代已生成结果。
- 身份参考、服装和场景按实际依赖准备；纯文字调度可以先做，缺图状态明确保留。
- 需要视频时才核验平台入口；只有首帧／首尾帧入口或明确端点控制才另做关键帧。
- 本次交付文字不表示表演、对白节奏或成片播放已经通过验收。
