# 模型适配：把导演设计编译成当前入口可接受的输入

适用节点：关键帧、视频提示词、声音、剪辑与文字自检。初次核验：2026-10-16；本轮增补：2026-10-21，Asia/Shanghai。旧版记录保留其原核验范围；本轮补充 Seedance 2.5、Kling 与 LibTV 来源样本入口对照。默认只准备文字资料；本页不授权上传、付费生成或发布。

## 平台通用层与工具适配层

2026-10-19 Clip流程补充：六区块是项目创作包，不是跨平台通用API。身份参考、首帧、首尾帧按实际入口选择，不能把四格身份板当首帧；完整规则见[Clip编译](clip-prompts.md)。精确时间轴保留为导演目标和实际结果的比较依据，输入文本的长度不与可控性简单成正比。

2026-10-19补充记录核验了[Runway Gen-4指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)：文字与图像共同影响输出，该模型采用正向表达；重复图中细节或时间安排过密可能影响结果。[Google Veo指南](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/video-gen-prompt-guide)则提供负面提示方法，建议列出排除元素。两者说明必须按模型/入口编译，不能称所有模型都不识别否定。上述网页可读不证明用户账号、上传、计费或生成通过。

先完成平台无关的镜头设计，再按用户选择的模型与入口适配。用户本步要求视频提示词时，由 `aigc-video-prompts`（视频提示词） 在同一交付按 [Clip编译](clip-prompts.md) 编译，每条 Clip 只给一个保留六区块与 STYLE LOCK 八项的完整主复制稿；平台未知时交完整通用稿，在框外注明平台适配与媒体生成未执行，不另给扁平化稿。只有已核验入口明确要求格式编译/字段分流，或用户明确要另版时，才额外交平台适配版并说明内容去向。只要策划或图片时保持本步范围，图片提示词不套六区块。

| 层 | 保留什么 | 不混入什么 |
|---|---|---|
| 创作与连续性 | 本镜目的、角色和物体状态、三要素、主要动作、结束状态、前后衔接 | 未核验参数、平台语法猜测 |
| 平台适配记录 | 平台、模型完整版本、入口、输入角色、素材映射、时长和画幅、来源日期 | 未经生成的效果结论 |
| 可发送正文 | 当前任务所需的明确视觉和动作描述；已核验入口支持的素材指代 | 上传操作、来源讨论、方案候选、未填变量、本地管理 ID |
| 外部操作与交接 | 上传哪个真实文件、绑定何种用途、选择何种已核验设置、声音/剪辑安排 | 假称附件已上传或平台已接受 |

保留“重要内容前置”的创作原则：先让读者和模型看见本镜不可丢失的目标、身份绑定或主要行动，再补支持细节。**它不是跨模型、跨版本的词序权重保证。**未经公开证实，不解释成每个词随位置获得固定权重；也不承诺重复词句就会更准确。来源差异见下文。

### 最小适配记录

每次有平台专用输出时，记录：`platform`、`model_version`、`entry_mode`、`verified_at`、`sources`、`input_mapping`、`settings`、`unverified`。这些是本工作流字段，不是任一平台的 API 字段。

- `entry_mode` 区分文生视频、首帧、首尾帧、多模态参考、编辑、延长。相同模型不同入口也可能接受不同输入。
- 未查看用户界面时，写“入口未验证”，不能从官网展示推定账号有权限。
- 输入数量、素材格式、可选时长、分辨率、音频、字幕、价格和参数在实际使用前按当前入口复核；旧记录作为线索保留。
- `unverified` 明列账号可用性、界面接受、生成结果和播放验收；官网可读不能代替这些证据。

## 静态首帧与动态提示词的分工

**静态层**决定开始时已经存在的东西：主体外观、站位、姿态、接触关系、构图、照明、景深和空间。**动态层**决定此后发生的变化：谁先做什么、身体如何移动、物体怎样响应、相机何时移动、最终停在哪里。图片和文字共同影响结果，因此要检查二者是否冲突。

首帧中的跑动姿态、扬尘、运动模糊会暗示运动。需要静止车辆时，不宜把飞扬尘土和明显速度拖影保留在首帧里，再靠文字要求车辆完全停住。此冲突有 Runway 官方说明支持，不能只靠延长提示词修复。[R2]

教学示例：以下是新写的文字例子，不对应已存在或已上传的文件，也不表示一部真实作品已交付。正式交付时先根据目标作品确认参考状态。

**关键帧图片正文：**

```text
室内侧面中景，一名围红围巾的青年坐在木桌左侧，右手停在桌上一只完整白瓷杯的杯把旁，手指尚未接触杯把。杯子位于画面中部，桌面平稳。窗光从画面左侧照入，面部和右手清楚可见，背景为朴素的灰墙。
```

**配套图生视频的导演表达片段，非 Clip 发送稿：**

```text
固定机位。青年缓慢伸出右手，手指握住杯把，将杯子平稳提离桌面，靠近胸前后停住。他低头看向杯中，肩膀逐渐放松。窗光保持稳定。
```

**外部上传与设置说明：**上述动态片段仅演示静态/动态输入分工，须按 Clip 契约编译后才成为完整视频提示词。它以符合静态描述的首帧为输入前提；实际文件存在并通过静态检查后，再在已核验的首帧入口上传。素材路径、镜头编号、时长设置与上传状态保存在交接记录中，不能直接混入上述正文。没有合格首帧时，将图片提示词标为待生成输入，不假装附件已就绪。

本项目Clip仍独立写明本场衣装和必须继承的可见状态；这与“避免无关外观重复”并行，不能把该建议理解为省略衣装或写出与已审首帧相反的服装。

纯文生视频没有可依赖的输入图，正文必须自行交代起始外观和空间；不能把图生视频的“少复述外观”原则照搬成文生视频省略主体。

### 同一场景的六类输入分工

以下为原创教学对照，**不是完整 Clip 发送稿，也不是六次生成方案**。共同设计为：青年穿藏蓝衬衫、深灰长裤、红围巾，坐在窗边木桌左侧；右手从尚未接触杯把开始，握住白瓷杯并提到胸前，低头看杯，肩膀放松后停住；固定侧面中景、左侧窗光。声轨仅含室内环境声、衣料轻响和取杯拟音，不设对白或BGM。所有素材名均为教学建议名，未生成、未上传、未绑定。

| 输入路线 | 输入负责什么 | 完整 Clip 正文仍须表达什么 |
|---|---|---|
| 纯文生 | 没有输入图承担静态信息 | 独立写全身份外观、本场衣装、木桌与窗户位置、手杯起点、固定机位、动作过程与终态；不能引用不存在的图 |
| 身份与场景参考 | **红围巾青年身份参考图_v001**锚定声明的身份特征；**窗边木桌场景参考图_v001**锚定木桌、窗户与光源关系 | 每条写全藏蓝衬衫、深灰长裤、红围巾；另定本镜机位、手杯起点与动作，不把身份板构图当视频第一帧 |
| 首帧 | **窗边青年取杯起始帧_v001**提供手尚未碰杯把的单幅起点及构图 | 写从起点开始的伸手、握持、提杯与停住，以及需保持的衣装、空间和照明；首帧必须与文字相容 |
| 首尾帧 | **窗边青年取杯起始帧_v001**与**窗边青年持杯终止帧_v001**分别约束两端，终帧为杯在胸前、低头看杯 | 仍写两端之间的动作因果、机位与连续状态；两张图不自动规定中间过程、切镜数或准确到达秒点 |
| 延长／编辑 | **窗边青年取杯实际视频_v001**必须是待延长或待编辑的真实目标视频，不能只绑定为风格参考 | 延长承接真实终态，再设计持杯后的动作；编辑明确修改区间、修改内容与保留项。两种任务分别核验，未获得真实视频前只交草案 |
| 独立音轨 | **窗边取杯环境与拟音轨_v001**作为后期音轨；只有已核验入口支持相应音频用途时，才另行映射为生成输入 | 保留相同声音事件、触发点和音量关系，注明后期对齐；画布有音频连线不证明模型会使用该音轨 |

前五行用于比较视频输入或任务类型，独立音轨是可与它们配合的声音路线，不是必须二选一的视频入口，也不新增项目`entry_mode`枚举。这些路线按当前入口与素材选择，不要求全部制作。参考图负责已声明的静态信息，正文负责动作、镜头、时序和必须重新说明的状态；二者合起来仍须完整、无冲突。实际交付使用用户选定的完整素材名与真实映射，逐条保留六区块和 STYLE LOCK 八项；表中片段不能单独复制成“默认短版”。

编译到实际入口时逐项核对：身份参考的用途、本条衣装、空间与起点、每镜动作/切点/终态、对白原文和声音轨道、排除项分别去了哪里。若入口不接收某类输入，标明未支持/待核验并给出对应的外部制作安排，不静默丢项，不杜撰字段；只有实际入口要求或用户要求时才另交字段适配版。

## 动作密度、复杂动作与时间

镜头表的时长是创作和剪辑计划；提示词中的秒数是模型控制请求。两者不能直接等同为模型已准确完成的时间点。

动作密度以新增任务判断，不能只数动词：抓杯、抬杯、停住可以是同一个连续动作；抓杯时另一个人冲入、灯熄灭、人物翻滚、相机绕行并切换场景，会同时引入多个难点。

1. 为主要动作写起点、准备、接触/发力、结果和结束状态；只保留观众理解所需的细节。
2. 高动态、多角色交互、遮挡、持物、镜头切换、对白分别增加控制难度。出现多个独立结果时考虑拆镜，或先验证其中最难的动作。
3. 拆段保留动作阶段、手持物、身体朝向、屏幕方向和声画接续；不把每段重置成同一张人物站立照。
4. 若用户要求具体镜头数，按情节功能给出数量和各镜作用；不要为了降低模型难度删除必要剧情，应通过素材、拆段或后期完成。
5. 时间过短时，优先删去非必要动作或调整剪辑计划；不要把多个完整事件挤进同一瞬间。必要的精确节拍在后期校准。

这些是本工作流的制作判断，不是所有模型的统一硬上限。Seedance 和 Runway 对时序表达的官方建议不同，须读下面的版本适配。

## Seedance 2.0：有完整操作指南，仍须核验当前入口

以下为火山官方提示词指南的简要归纳，页面标注更新于 2026-09-22。[S1]

- 素材逐项绑定用途；编辑、延长应直接指代目标视频，避免被解释成参考生成。
- 复杂视频按镜头顺序组织；精确秒数控制不稳定，不宜强制逐秒安排。
- 动作交代部位、幅度、速度及承接；一个镜头尽量一种运镜。快速复杂动作可分段生成后剪辑。
- 人脸排障建议面部特写配合全身图，并把需要精准参考的素材指代放前面；这是特定参考场景建议，不是通用权重公式。
- 指南使用无字幕等约束表达，但承认无法百分之百避免字幕。不要把约束语当成保证。

本工作流据此采用“素材作用说明 + 镜头事件顺序 + 必要约束”的组织方式。先用清楚的主体绑定防止指代混乱，避免重复一长串身份描述。角色多视角、全身与面部素材应按具体问题选择，不能推导成所有对象都需要同一组参考图。

发布说明确认 2.0 接受文字、图片、音频和视频，并介绍多镜头音画、编辑与延长；其中 9 张图、3 段视频、3 段音频及 15 秒输出是该版本发布说明的能力描述，不能据此假定所有产品入口都开放相同限制。[S2] 模型页是功能概览，不是 API 或账号权限证据。[S3]

**示例素材绑定片段，非 Clip 发送稿；仅展示输入分工，标签只在当前入口确实采用且素材已经映射时使用：**

```text
图片1中的红围巾青年为主角，图片2提供木桌与窗户的位置关系。镜头1：侧面中景，青年缓慢走到桌边，将手掌轻放在桌面，相机保持固定。镜头2：切到青年右手的近景，他握住白瓷杯的杯把，将杯子平稳提离桌面后停住。
```

**外部上传说明：**在交接文件中分别列出图片1、图片2对应的真实文件及版本；标签必须按平台实际分配结果替换。图片1/图片2只是此教学例的角色标签，不代表文件已存在。若入口要求其他引用语法，完成适配后重新交付干净正文；不要把“请上传图片1”写进生成提示词。

上段保留2026-10-16的标签映射教学示例，不作为现行交付模板。新交付仍按同版handoff使用真实素材完整名称与已核验映射；含素材引用的唯一主稿用可渲染Markdown并加粗完整名称。上文六类输入对照中的建议名同样不代表真实资产就绪。

## Seedance 2.5：单独建适配记录，不继承旧版上限

**2026-10-16历史记录：**官方模型页介绍最长 30 秒单次生成、最多两次延长，以及参考与编辑能力改进。[S4] 当时足以确认需要区分 2.0 与 2.5，但未完成 2.5 的详细接口、用户入口或提示词实验核验。下面保留当时对照，不能作为2026-10-21新增取证的全部状态。

| 项目 | 2.0 当时证据 | 2.5 当时证据 | 工作流处理 |
|---|---|---|---|
| 提示词指南 | 已读取火山完整指南 | 本次只核验模型介绍页 | 通用创作法可复用；2.0 专用语法不能宣称已在 2.5 验证 |
| 时长介绍 | 发布说明介绍 15 秒输出 | 模型页介绍单次最长 30 秒 | 实际提交前核对选定入口，不写成系列永久上限 |

| 账号与实际结果 | 未验证 | 未验证 | 界面、生成、播放验收均为 NOT_RUN |

不要把较长单次时长解读为可以任意增加事件数量；导演设计仍需有可理解的动作与空间。也不要因名称升级就宣称角色一致性或物理正确性已经获得保证。

### 2026-10-21增补：多镜、时间段与当前入口

2026-07-31发布说明确认2.5可在一次最长30秒的生成中组织多个逻辑相连的镜头；可用时间段描述叙事、视角、运动和节奏，也可对指定片段作定向编辑。[S5] 因此保留明确时间计划，不把2.0指南的时序建议写成2.5禁止时间控制；**支持控制不等于本项目秒点、切镜或对白已经准确命中**。单镜内的时间段也不等于多个Shot。

## Kling：3.0、3.0 Omni与LibTV O3标签分别记录

## Runway：Gen-4 与 Gen-4.5 分别处理

**Gen-4 官方指南**建议从简单动作开始，逐项添加主体、环境或相机运动；图像建立视觉起点，文字重点描述动作。过度重复图中外观、在短片段塞入多个场景与变化，会增加不确定性；该指南要求正向措辞，不支持把负向提示词当作常规控制手段。[R1]

**当前 Runway Academy 指南标注 Gen-4.5**：输入图是首帧；图生视频文字重点写运动。清楚表达比固定顺序重要；可以使用事件先后或粗略时间点，并让复杂程度与片长相容。必要时补充新出现元素、变换或交互所需的视觉信息；首帧中的隐含运动也应与文字一致。[R2]

适配时采用以下判断，不要求固定语序：

- 参考图已建立的人物身份用清楚的简短指代保留；多人分别行动时用位置或稳定描述消除歧义。
- 需要静机位时描述固定相机及画面中实际发生的小动作，而不是只堆“不要移动”。
- 新元素入画、服装变换或物体转化需要在正文写出如何发生；不能为了“只写动作”而省掉必要目标状态。
- 复杂时序先判断是否适合当前片长，再决定拆段；不能把 Gen-4 的单场景倾向写成 Gen-4.5 永远不能顺序叙事。
- 用末帧续接下段是当前指南提供的方法，但接段仍需编辑和连续性检查，不能承诺无缝。[R2]

- 相机、角色、画面三要素是否分别明确；固定机位与移动机位是否冲突。
- 首帧是否真的处于动作开始状态；手持物、朝向、接触关系是否能进入本镜动作。
- 本镜是否有可观察的结束状态，能交给相邻分镜；没有通过秒数格式假装解决衔接。
