# 调度编译为 Clip 提示词

v004 · 2026-10-20。用户已批准Clip候选v001，现落实为`aigc-video-prompts`的共享编译规则。用户说“把这份调度转成能直接发的 Clip”即可；后台处理分组、编号、连续性、绑定与模型语法。先读 [交接](handoff.md) 与 [模型适配](model-adaptation.md)。

## 三个单位与交付版本

- **Shot**：一次连续观看/拍摄设计，含可连续变化的机位或景别。移动相机不自动产生新 Shot；有意切换观看画面时再标切镜。
- **Clip**：一次生成请求对应的素材片段，可含一个或多个 Shot；长 Shot 可跨多条 Clip，编号不因平台时长而失去原叙事身份。
- **成片**：剪辑、声音和后期后的最终作品。Clip 数由实际内容决定，不能强制几十条。

**默认每条Clip只给一个完整主复制稿**，保留六区块、STYLE LOCK八项及全部导演约束。平台未知时，这就是完整通用模板，在复制框外注明“平台适配未执行”；不再附加“通用正向正文”、压缩版或散文式发送稿。仅当已核验的实际入口明确要求格式编译/字段分流，或用户明确要求另版时，才另交对应的**平台适配版**，逐项对应完整稿的内容并说明各字段去向。完整创作包始终存档，不以适配版替代。

六区块是本项目交付格式，不是所有模型共同的API语法，不能声称各平台都接收这些标签。实际支持的图像标签、负向字段、时长和原生声音才进入对应位置；其余保留为正向表达或明确的外部制作/检查约束。上传/设置与可复制内容分开交付，用户不需手动改写模板。

## 输入与缺项处理

接收完整调度：每 Shot 的空间、相机、前后景、主体、衣装、动作/台词/声音、时间片与起止状态。缺某一个字段只补该缺口；不能用 Clip 模板猜测并改掉原故事。

通过交接协议读取当前作品脉络，核对最新剧本、全片/段落风格及用户修改；声音任务同时读取[声音资产协议](voice-and-music.md)。沿用当前CHAR→VOICE和Shot→BGM的版本、用户选定素材与使用区间，不能把角色在本句哭泣当成更换声音身份，也不能凭某个Shot情绪词推翻全片音乐基调。用户已要求先做人物音色与BGM时，保留这些资产交付和绑定依赖；原生视频能发声不构成省略理由。

身份/场景参考和首帧用途不同。人物参考图默认锚定已声明的脸型、五官、发型以及指定身份标记；当前 Clip 衣装由本场 OUTFIT 描述完整展开。参考图中的衣服在转换资产时忠实保留，不因此成为剧情服装来源。参考图采用哪种构图或几张输入由资产规范、实际入口和本条需要决定，不固定图数。

无真实图时可以交资产图片提示词和有明确状态的 Clip 草案；不能虚构 `@Image1` 已上传。如果用户选择纯文生，写全身份/空间/静态起点，不依赖图片。平台未定可以交完整通用稿，但图像依赖尚未满足的稿件不能称为可发图生版。

## 编译步骤

1. 建源 Shot 清单，锁定已确认台词/人物/物件/事件；保留导演意图，逐项展开可观察表现。
2. 按空间、时间、事件/对白密度、参考数量与模型单次能力分组。每条 Clip 明确起止状态；多镜 Clip 标切点，连续长镜拆 Clip 保留连接意图。
3. 为 Clip 建从0秒开始的本地时钟；另保存 Shot 内区间映射。按动作、台词、反应和声音触发细分连续时间片，覆盖到本条总时长；单镜有连续时间片不等于发生切镜。多镜的Shot和切点另行标明，时间片继续沿用同一Clip本地时钟。不要把整片第21.5秒直接当新Clip的第21.5秒。所有数值是设计目标；实际回填另存。
4. 每条Clip完整填六区块与STYLE LOCK八项，首句优先写主体/核心行动。不能将多条Clip的风格合并为一个共用表，也不能改成一段概述而省略结构。消除相反的机位、服装、灯光和动作；空间、角色情绪必须能转成客观画面。
5. 默认保留完整六区块主复制稿；实际入口明确要求编译/字段分流或用户要求另版时再生成适配版。素材标签来自真实映射；衣装在各独立Clip重新定义；必要起始状态不靠“同上”。
6. 检查每条Clip覆盖的Shot区间、时间总和、声音触发、图文冲突与依赖；有适配版时与完整包逐项对照，不能因适配丢掉关键内容。

## 六区块契约

| 区块 | 内容 |
|---|---|
| `[STYLE LOCK]` | 逐条展开下文八项，按作品填写；每条Clip重复写全本条必要内容 |
| `[参考图锚定]` | 按素材全名逐项写用途、锁定特征与本条重新定义的状态；区分人物、动物、道具、场景及首帧。实际标签依平台与真实映射处理；纯文字稿明确其文字基准 |
| `[空间与站位声明]` | 场景地标、所有行动相关主体/物体、位置/距离、前后关系、初始朝向与相机观察方向 |
| `CLIP — 名称（总时长·单镜/多镜）` | Shot列表，每镜景别+具体裁切、机位+运镜、连续时间片、明确主语的动作/对白/声音/环境、入口出口；每个切点写清楚，最后时间片写终态 |
| `[BGM & 声音设计]` | 声源、声音质感/音量关系、画内外位置、对白原文及节拍、BGM进入退出与后期空间；与Shot时间轴一致 |
| `[NEGATIVE]` | 仅列本片确需排除的元素，如多余肢体、水印、非剧情文字；黑白、颗粒、字幕等按创作需求选择，不做通用黑名单 |

六区块按表中顺序逐条完整交付，包括纯文生或单镜Clip；不用“同上”、共用风格表或普通段落代替。不得默认另给扁平化的第二主稿；仅在前述实际入口或用户要求的条件成立时编译适配版。实际负向字段分流也不改变六区块完整包的存档。完整包缺依赖时是草案。内部模板可有字段标签，正式发送稿必须全部展开，无【待填】、本地路径或读取项目文件的要求。

### STYLE LOCK 八项

下列八个字段在每条Clip内分别展开；它们规定要表达的信息，不统一作品的审美、帧率、摄影媒介或画幅。无人画面中，人物运动项写明人物不适用，并展开当前主体运动规则；具名角色项列本条实际主体，不凭模板增添人物。

1. **一句话风格锁定**：前置核心主体、行动与本条情绪/信息变化，点明必须控制的画面目标；不能只写“电影感”等抽象词。
2. **色调**：本段主色、明暗、饱和度、肤色或主体色及与相邻段的关系；只继承已经确认的风格。
3. **质感**：材质、表面细节、颗粒、光晕或绘制纹理的具体观感；胶片型号等仅在本作品需要时写。
4. **质感锁定**：整体表现媒介、摄影/渲染观感、运动模糊、镜头与焦点规则；摄影机固定或运动与正文一致。提示词帧率观感不等于输出文件帧率。
5. **物理照明锁定**：可解释的光源位置、方向、亮度关系与段内变化，保证人物、物体和背景同处一套照明。
6. **人物运动物理**：逐人写本段衣装、起始姿态、动作链、接触与等待关系，表情落到目光、肌肉、呼吸等可见/可听表现；动物或其他主体使用适用的运动和接触规则。
7. **场景物理规则**：活动边界、承托/持握关系、物体位置与允许变化；复杂动作保留因果，不能靠删除事件消除冲突。
8. **具名角色声明**：列全本条实际出场的人物、动物及其他叙事主体，用稳定名称区分并对应参考素材或完整文字特征；不把场外主体误写为出场。

### 参考锚定按资产类型表达

| 类型 | 锚定内容 | 本条正文另行定义 |
|---|---|---|
| 人物 | 已明确的身份、脸型五官、发型及身份标记 | 本段衣装、姿态、表演、走位；衣装可按本条定义，不自动继承身份图衣服 |
| 动物/生物 | 体型、毛色/纹理、眼睛与形态比例 | 姿势、动作、接触位置；不能套用人物五官或衣装重写规则 |
| 道具 | 外形、部件结构、材质、稳定标记 | 开关、破损、持握、摆放和操作状态；不因人物衣装独立定义而重写道具结构 |
| 场景 | 地标与物件的相对布局、稳定光源位置 | 当前Shot的机位、高度、景别、焦点、人物站位与允许的场景变化 |
| 实际首帧/末帧 | 用户选定的真实端点与已反馈状态 | 由端点发生的动作与终态；身份图或场景图不自动拥有端点用途 |

逐项用完整素材名说明“锁定什么、本条定义什么”；同一图兼有用途时说明各用途，不扩大到未声明信息。画布节点名、模型标签和文件名分别核对，不能由“图片节点4”推定`@Image4`。支持标签且真实映射到位时才在正文使用；入口按槽位/已连节点接收素材时用实际映射，不要求虚构标签。缺实际素材或必要映射时写绑定计划、保持依赖草案；纯文生以完整文字定义主体与布局。

### 空间、时间片与终态

先声明地标坐标与相机观察方向，再写人物身体左右、画面左右和前后层次；多个主体同场时每个动作、视线、台词和反应都具名。景深须兼顾叙事：若背景人物的点头/表情承担信息，写明回应幅度与可辨程度，不能同时要求完全不可辨。

按事件顺序细分时段，说明谁先做、什么触发回应、谁等待；声音区复核同一触发顺序与次数。最后时间片明确人物位置/姿态/视线、持物或接触、关键物件位置与状态、相机终点；多镜还写清切点前后如何接续。后一条以用户反馈的真实结果承接，不将本条计划终态当作已经生成的事实。

### 每条正文外的画布连接说明

声音也逐条列入用途映射：角色音色样音用于身份参考，完整对白音轨用于台词/同步，BGM用于配乐，三者不可互换。实际入口接受哪种音频才连接哪种；不支持时交给后期声音路线，不能假装声音卡或音色ID已被视频模型消费。`[BGM & 声音设计]`沿用调度的进入/延续/变化/收束与时间区间，多Shot一Clip不重复启动同一音乐；独立对白/BGM与原生音轨的保留、关闭或后期替换方式放外部执行说明，避免重复叠加。素材未生成时保留完整声音设计和框外依赖状态，不编造文件或标签。

按[画布交接](canvas-handoff.md)逐条列素材全名、用途、实际状态、组合关系、输出节点和具体缺口；多条Clip各给一份，不合并成需要用户自行拼装的总表。未创建的名称写“建议名称”。是否加入上一Clip由实际连续性用途与入口决定；首帧图片、身份参考板与上一段视频分别列明，不固定参考数量或默认选择全部旧节点。

## 语言纪律

正文以正向物理状态表达：`固定机位`、`声轨仅含对白与环境声`、`本场服装为米白开衫与深蓝长裤`。把排除项集中在创作包末尾；避免 `no/never/not` 或中文“不/禁止”对模型下反向指令。**已确认台词、片内文字、专有名称中的否定原文完整保留**，不通过简单关键词替换破坏内容。

“伤心/开心/震惊”改成可见呼吸、肌肉、目光、嘴唇、手和身体反应，带触发顺序；不能把所有悲伤都替换为同样流泪。旁白情绪指示也要落到音量、语速、停顿和音色。

禁止项与原例的冲突须显式修订：原例正文 `not animation` 改为正向实拍风格描述；“无BGM”改为“声轨仅含对白和环境声”；宠物是否出现项圈写在该Clip的排除约束中。参考图机位不是剧情机位，须用本Clip的真实相机位置/高度/朝向覆盖构图意图；实际是否成功仍需检查。

## 发送与平台适配

| 条件 | 处理 |
|---|---|
| 有独立负向输入字段 | 主正文用正向描述；将NEGATIVE内容单独交该字段，标明真实UI/API映射 |
| 官方支持正文排除说明 | 按该模型指南组织必要约束，不能承诺排除绝对成功 |
| 实际入口已核验不支持负向 | 在适配版中写期望状态，检查表核对排除项；NEGATIVE保留在完整包，不强贴到该入口 |
| 平台/入口未知 | 保留含NEGATIVE的完整六区块通用主稿，只在框外说明适配未执行；不自行生成另一份删区块或散文式正文 |
| 多模态身份参考 | 将真实角色板绑定身份，场景图绑定环境；每Shot独立写机位，不能把四格拼版当视频第一帧 |
| 首帧/首尾帧入口 | 按所需端点准备单幅静态图，由用户在LibTV确认可用；真实文件或节点标签仍需到位才执行实际生成 |
| 无原生音频 | 交同时间轴的对白/音效/音乐制作稿，说明音频/口型实际待完成，不默删声音设计 |

原生分辨率、帧率、镜头光学参数等若仅为提示词风格请求，应明确它们不是文件技术参数。使用前按模型/入口/核验日期记录能力，不能靠写“4K/24fps”证明输出规格。

## 项目落盘与检查

项目内使用 `prompt_layout=clips`、`clips_file` 及 `spec/clip-contract.md` 的兼容契约。`03_分镜表.csv` 保留原Shot编号和故事信息；Clip→Shot区间写 `04_生成提示词/clips.json`，内部完整创作包写同目录的Clip工作稿；`本次发送.md` 每个Clip标题下只有当前可复制正文。标题中的管理ID在代码块外。

项目映射的Clip编号统一为 `EP01_CL001`（`EP`+至少2位数字+`_CL`+至少3位数字），Shot编号为 `EP01_SH001`。不要用示意性的 `CLIP-001` 写入正式映射或发送标题；纯聊天也尽量采用同一编号以便后续落盘。

映射使用 clip_id、duration_seconds、entry_mode、references（label/role/file）、segments（shot_id、shot_start_seconds、shot_end_seconds、clip_start_seconds、clip_end_seconds）。Clip区间从0到总时长连续覆盖；源Shot区间跨Clip合并后与原计划相等。素材真实、用途正确、台词/物理/审美仍由内容审查，结构校验不能代替。

安装包脱离项目时可在聊天提供同样映射与交接，不凭空创建或声称项目契约已通过。旧作品继续 per_shot，不批量改历史文件。

生成后由用户在LibTV观看并反馈真实首末状态、实际时长、台词、声音及偏差；Codex据反馈记录来源并决定如何修改或承接。用户已确认的结果无需再次上传复审，未知状态保持未知，计划姿态不覆盖真实结果。

v002修订依据：独立文字执行使用了不符合项目契约的内部Clip编号，现将编号规则在编译入口直接展开；原始输出和v001源快照保留，不能把该草案说成数据门禁已通过。
