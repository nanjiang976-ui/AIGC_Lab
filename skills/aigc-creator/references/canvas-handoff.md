# 每条 Clip 后的 LibTV 画布交接

v001 · 2026-10-20。适用于用户手动在 LibTV 画布多选素材、生成下一节点的工作方式。它是提示词之后的操作说明，不改变 Clip 正文格式，不代表某个模型已支持全部参考输入。

## 让用户直接找到该选谁

每条 Clip 正文后，分别说明：

- **本条要生成什么**：Clip完整名称和视频输出节点；只有建议名称时明确“建议命名”，不伪称节点已创建。
- **本次多选什么**：列每一个实际图片或片段的完整素材名；有用户提供/截图可见的画布节点名时一并列出。禁止“参考A/B”“角色图同上”等不透明代称。
- **每个输入负责什么**：人物身份、生物特征、道具结构、场景空间、实际起始状态或动态参照；同一素材可有多项用途，但不能把身份板默认为首帧。
- **组合关系**：完整素材名 + 完整素材名 → 当前Clip。说明上一段是否要加入；没有连续性用途时不用顺手加入全部旧片段。
- **生成前核对**：实际入口/模型是否接收这些输入、名称与标签是否对应、尚缺哪一项。仅列影响本条执行的具体缺口。

这些内容放在正文复制框之外，不写进模型的画面描述。多个 Clip 各给一份，避免要求用户从全局大表自行拼输入。

## 名称、节点与标签

完整素材名是给人识别的名称；画布“图片节点 4”是实际节点名；模型 `@Image…` 是入口识别的素材标签。三者不能按数字互相推算。可以建议将节点重命名为素材全名，但没有执行过就不能写“已重命名”。

当前入口需要素材标签且对应关系尚未确认时，先给清楚的素材绑定计划和完整文字草案；不伪造标签，也不强制用户把已自行验收的媒体重新上传审查。不需要标签、直接按输入槽或已连节点接收参考的入口，使用实际节点与槽位映射即可，不把缺少`@Image`当成新的阻塞。所需映射到位后，仅完成适配，保持已确认剧情和调度。

只选本条必需的资产。人物图负责身份，本段衣装由正文定义；道具图负责稳定结构，开关/损坏/持握等当前状态写正文；场景图负责布局，本Shot独立设计机位。

声音输入同样使用完整名称并区分用途：人物音色样音、已生成的完整对白、BGM成品不是一种输入。按当前入口选择可接收的声音；不接音频的入口保留明确的后期绑定，不假称音频已经参与视频生成。音乐节点须说明使用哪个实际区间、是新起还是延续；角色音色ID或声音库关联不能自动推导为任意视频模型都支持固定音色。完整规则见[声音资产](voice-and-music.md)。

## 上一条 Clip 怎样接进来

先依据用户反馈确定上一条的真实结束状态，再按当前入口安排：

同时核对下一段动作必须接触的物件和空间是否已在实际起点中存在、位置是否已知，例如把印章放进木盒时，木盒不能仅因出现在下一段计划中就被当作已在末帧。缺少这类信息时指出具体缺口；若真实起点没有该物件，先设计有因果的进入方式，或提供经用户选择的起始图调整/切镜方案，不承诺复制末帧就能直接完成。

| 实际用途与入口 | 本条选择的输入 | 必须写清 |
|---|---|---|
| 当前入口已核验支持视频参考/延长 | 用户选定的上一条Clip视频节点，及该入口允许且确有必要的其他素材 | 视频完整名称、参照/延长用途和承接的实际动作状态 |
| 需要首帧且入口只接图片 | 从用户选定片段取得并确认的实际末帧图片节点 | 末帧图与原视频是两个素材；不能把视频节点充当图片 |
| 场景/时间切换，不依赖上一段输入 | 本条人物/道具/场景等所需图片 | 明确本条不选择上一Clip；保留叙事与声音上的衔接设计 |
| 视频输入能力或实际末态未知 | 绑定计划或条件分支 | 保持草案；只询问这个缺口，不宣称自动抽帧、自动无缝衔接 |

多选连线不等于各输入权重已设定，也不证明四格整板会被某个模型正确解析。若入口限制输入数量或用途，针对本条给出可执行调整；不要默默删掉关键人物/道具或假定平台自动处理。
