# 自动归类与入库

默认库：AIGC_Lab 的 `02_提示词库`。先读库 `README.md`、`入库规范.md` 和 `分类模块/00_使用索引.md`；需要哪些类别再读相应文件，不加载整库。其他项目明确指定自己的库时在该范围维护，不把资料跨项目搬运。

## 每次创作后的短流程

1. 识别本轮是否产生可跨作品使用的提示词表达、衔接结构或有效纠错办法。具体剧情、姓名、真实客户、私有资料和输出媒体本身留在作品里。
2. 将实例变为带明确变量的模块；保留动作次序、空间关系、必要约束与适用条件。参数化后只剩“高质量、好看”则没有入库价值。
3. 在索引与目标类别用关键词、目的、输入条件和既有 ID 查重；同一功能换几个形容词、角色名或地名不新建。
4. 无等价模块才分配类别内下一个未占用 ID，写到合适文件。同一用途的小修订沿用 ID 并升版本；旧版若已被作品或证据引用则先保留旧版区块/文件，不覆盖。真正不同的用法才新增 ID 并注明关系。
5. 同步索引与 `入库日志.md`，包括日期、来源作品/镜头/revision（初始库可写本地设计）、动作、新版本、理由与证据状态。记录后重读，核对 ID 唯一、链接、变量和计数。
6. 最终只报有意义的变化：“新增 1、复用 3、未实测”；零新增完全正常。纯复用在作品记录列出，不需给公共日志增加一串无变化条目。

公共库一个写入者；有并行创作时其他 Agent 交提案，由写入者重新查重分配 ID。目录写入失败或不可用时保留待入库条目并说明，不声称已保存。

## 模块必备信息

- ID、名称、类别/标签、版本、适用任务。
- 可复制的参数化正文；输入变量含义与缺省处理，缺关键值时不能默默使用占位符。
- 适用边界、依赖能力、常见不适用情形；平台专用参数放模型适配记录。
- 来源、建立/修订日期、验证状态、真实证据/失败条件。共享的来源和状态可放分类文件顶部；存在例外时逐条覆盖。

首批库统一为“未实测”。“结构审查通过”仅表示文字完整、内部不冲突；不改变效果状态。用户说“感觉更好”可记录为用户反馈，不能冒充 Agent 看过素材或测过模型。

“实测可用”需记录模型与版本/入口、日期、完整实际输入与参数、参考资产、结果位置、检查人、检查范围和失败边界。改变正文或条件后新版本回到未实测；旧证据仅属于旧版本。成功一次不证明跨模型、跨角色、跨片段稳定。

## 使用时组装，不整库复制

典型组合：主体/角色模块 + 场景模块 + 构图/光色模块 + 本镜头动作模块 + 必要连续性约束。把变量替换成实例并压缩成自然、可执行的正文；删除重复和冲突，如固定机位与持续环绕、正午硬光与均匀阴天漫射。

公共库允许模板变量；发送版不能有模板变量、未选方案或不存在的参考。实际使用的模块 ID+版本记在作品内部资料，外部模型正文无需含这些管理编号。
