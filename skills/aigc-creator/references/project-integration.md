# AIGC_Lab 接入与文件位置

创作根目录为当前使用的 AIGC_Lab 仓库，不绑定某台电脑的用户名或盘符。

路径优先级：用户本轮明确目录 > 当前有完整 AIGC_Lab 契约的工作区/其上级项目根 > 用户在当前会话已明确绑定且仍存在的创作根目录。用 `README.md`、`spec/harness-engineering.md`、`01_创作模板` 与 `02_提示词库` 确认项目，不能仅凭文件夹同名认定。只操作定位到的一个根目录；当前是其他项目且用户没有要求迁移时，不在那个项目悄悄创建 AIGC 文件，不扫描整盘查找仓库。

未能定位项目时先继续可完成的聊天创作，并询问保存位置；不要自行创建同名完整仓库、初始化 Git 或切换工作树。用户只要求聊天草稿时不强制创建作品目录。明确只读/不保存则不写文件；明确不入库则仅跳过公共库写入，作品资料仍按用户本轮要求保存。

## 进入或继续作品

1. 读取根 AGENTS.md、README.md、spec/harness-engineering.md、spec/plans/README.md 和验收要求。
2. 找到用户指定作品，读取 project.json、需求卡、设定与最新修改记录；不要以最大编号猜测用户指的是哪一部。多个候选且无法从上下文判断时只问作品选择。
3. 新作品按现有编号分配下一个唯一 WORK-NNN，从 `01_创作模板/作品模板` 复制，保留原文件。填写真实已知内容，DRAFT 可以留待定，不把空模板叫完成。
4. 单图保持短流程。图片系列/重复角色/视频需要台账时，复制 `连续性台账模板.md` 到作品 `07_连续性台账.md`；分段视频再复制 `分段生成与衔接模板.md` 到 `08_分段与衔接.md`。无此模板时按连续性协议创建最小等价表，不伪造参考路径。

## 持久化对应

| 信息 | 作品/库中的位置 |
|---|---|
| 用户回答、工作假设、待定项、下轮起点 | 00_创作需求.md |
| 故事与角色/衣装/场景/道具固定 ID | 01_故事与角色设定.md |
| 剧情节拍/对白，单图不适用说明 | 02_剧情脚本.md |

| 本轮实际可发送的镜头正文 | 04_生成提示词/本次发送.md |
| 候选提示词与未发送草案 | 04_生成提示词/草案.md（仅有需要时创建） |
| 实际媒体及生成记录 | 05_生成结果/ |
| 模块使用 ID/版本、差异、审查、参数、参考映射 | 06_修改与验收.md |

角色等 ID 为本地管理键，平台不会自动识别。作品的参考引用必须是真实存在的作品内相对路径；公共资产需复制到作品内并记录来源。避免引用到用户凭据、外部任意目录、符号链接或空文件。

## 版本和发送批次

原分镜表头不变：shot_id、duration_seconds、scene_id、character_ids、description、dialogue、image_prompt、video_prompt、reference_files。一个可单独生成镜头一行，图片时长为 0，视频/有时间轴漫剧大于 0。

编辑已准备/已验收内容前保留旧版本，递增 project.revision，status 回 DRAFT，对应 generation/review 回 NOT_RUN。历史媒体保留。草稿轮内也写明修改；不得把旧版结果重新标成新版 PASS。

分批制作时 `本次发送.md` 只包含当前可发批次，其余放草案；在修改记录写本批 shot_id 清单。如果完整作品尚有待定镜头或依赖未生成的前段终帧，保持 DRAFT。现有项目提示词校验按完整分镜覆盖，不得伪报为“批次校验通过”；批次只做明确范围的内容复核，完整作品材料齐备后再跑 prompts 门槛。

## 检查

在定位的项目根目录运行：

```powershell
python -X utf8 scripts/validate_project.py
# 将下面目录替换为实际作品目录；不对模板或零作品声称交付成功
python -X utf8 scripts/validate_project.py --work "04_作品项目/WORK-001_实际名称" --phase prompts
python -X utf8 scripts/validate_project.py --work "04_作品项目/WORK-001_实际名称" --phase delivery
```

仅准备草稿时运行结构检查并说明未到 prompts/delivery 阶段。有文字交付需做内容复核，媒体交付还需真实生成证据、播放/视觉检查。检查失败保留准确状态，不能填造用户审核人或虚假证据来通过。当前脚本不专门校验新台账，逐项人工/Agent 复查其逻辑。

仓库 `skills/aigc-creator/` 是可分发源文件，用户级技能目录中的 `aigc-creator/` 是安装副本。Git 推送只包含仓库副本；修改 Skill 时先比较两处，保留各自改动，再同步并校验，不假定会自动双向同步。仓库的使用说明给出安装和更新步骤，迁移设备时还要安装该 Skill 并打开 AIGC_Lab 工作区。首次安装后如本会话技能清单尚无它，提醒重启 Codex 并在新聊天确认能选到；允许隐式调用不等于已证明每次都被自动选择。
