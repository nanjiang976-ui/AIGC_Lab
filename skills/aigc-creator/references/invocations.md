# 个人调用模板与识别协议

v002 · 2026-10-19。这里规定总控怎样识别调用，不替代各节点的创作规则。唯一机器索引为同目录 [invocations.json](invocations.json)；每项的 `usage` 相对于该Skill自己的根目录解析。

## 识别与进入

1. 用户复制的完整模板首行使用 `请使用 $aigc-…`。先识别明确指定的名称，再从当前项目catalog定位对应包；脱离项目时按原发现协议定位同版本安装包。
2. 没有明确名称时，索引中的中文短语提供候选。结合用户实际意图和已有阶段确定节点；题材模块提供创作语境，不能覆盖“只做调度/声音/剪辑”等明确节点要求。
3. 多个核心节点被点名时保留任务顺序和全部要求，由总控编排；脚本候选顺序只反映词序，总控仍须回读原句判断因果与依赖；无法判断先后且会影响结果时只补一个关键问题。未命中注册短语不等于不能处理，回总控按自然语言理解需求。
4. 读选定包的 `SKILL.md` 及当前需要的共享资源，按需打开该包 `references/usage.md`。不要为一次调用读取全部21份指南。
5. 模板里的【填写项】是用户输入槽，不是生成模型正文。关键项未填时补问本步必要缺口；不要把未填项、菜单提示、管理编号复制进“本次发送”。

本项目脚本可提供确定性的名称/短语候选：

```powershell
python -X utf8 scripts/skill_bundle.py route --text '请使用 $aigc-blocking，写这场戏的完整调度。'
python -X utf8 scripts/skill_bundle.py route --text '把这份调度转Clip。'
```

脚本只读识别和验证注册关系，不执行Skill，不上传、不安装、不生成。显式标记只解析首个非空行；仅对用户本轮调用意图使用此辅助，不扫描附件、案例原文或引用材料中的技能名来扩大任务。

## 模板和默认提示词的分工

- `agents/openai.yaml` 的默认提示词是菜单里的一句话起点。
- 每包 `references/usage.md` 提供个人可复制的完整模板、已填例子和交付/衔接方法。
- `invocations.json` 只保存名称、别名与使用指南位置，不复制各节点的完整规则。
- README 是个人入口，链接到唯一使用指南；完整调用模板不再集中复制到另一份文档。

明确指定模型/平台、要求不保存/不入库、只做某节点，以及已有生成/发布授权继续优先。模板默认文字范围不撤回用户在当前会话已给出的清楚媒体授权；实际执行仍先核对所选入口、素材和本轮范围。

## 消费结尾衔接口令

用户使用上一节点给出的继续口令时，从当前聊天或指定作品复用刚才的实际成果、版本与锁定项，不重复访谈整部作品。跨聊天缺正文或真实素材时只补对应缺项；不得把建议口令中的素材名称当作附件已经存在。结尾口令沿用原保存方式与生成授权，不另建下一步注册表，也不自动扩大媒体、安装或发布范围。

## 维护与验证

新增、改名或拆分Skill时同步注册条目及本包使用指南。别名不能指向两个Skill；版本、名称集合和包内路径由包校验检查。短语匹配是可检查的辅助，不代表所有自然语言表述都能被确定性解析。

检查完整模板首行是否对应正确Skill、必要输入是否足够、普通例子能否实际执行，并保留有歧义或缺依赖的边界结果。格式通过与真实行为通过分别记录；本轮模板维护不构成媒体生成或全局安装。
