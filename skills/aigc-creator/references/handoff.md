# 节点交接协议

版本 v002，2026-10-16。本协议在本套件中只维护一份。作品根目录依照 [项目接入](project-integration.md) 定位。用户明确完整 AIGC_Lab 工作区时，验证项目契约后优先读该根 `skills/aigc-creator/references/`；脱离项目时再用当前包安装根/技能元数据找到配套总控。先确认共享文件和当前套件配套，不能把新工作树的叶节点混接到旧全局总控。只安装了叶节点时补齐总控依赖，不猜测绝对路径。

套件身份在各 SKILL.md 的 `metadata.bundle` 与 `metadata.bundle_version` 中；本版为 `aigc-lab` / `1.0.1`。脱离项目时比较叶节点与总控这两个字段；缺失或不同则报告需要完整同步，不把“同名”当“同版”。项目内还可与 `skills/catalog.json` 的 bundle_version 核对。

## 三类职责

| 层 | 决定什么 | 不代替什么 |
|---|---|---|
| 总控 aigc-creator | 当前阶段、模块选择、已有资料、依赖和下一步 | 不把所有节点全文重复一遍 |
| 类型模块 | 此类内容的目的、叙事/信息策略、节点取舍、专用验收 | 不复制共享生成节点，不重问完整需求 |
| 共享节点 | 当前阶段的具体创作判断与交付 | 不擅自重写上游确认的角色、剧情、事实 |

用户只要求某一节点时直接进入该节点，先检查必要输入，缺哪个补哪个。完整 PRD 先体检，不重新访谈；新会话从当前版本/下轮起点恢复。一个主模块即可覆盖大多数任务；广告剧情片等混合请求可加一个有必要的次模块，先声明主目标，冲突取舍由用户目的决定。

## 每次交接的最小记录

可用 Markdown 表或现有作品文件表达，不强制创建额外数据库。数据有来源就引用源文件/章节，避免维护两份事实。

| 字段 | 内容与判断 |
|---|---|
| 作品与版本 | work_id、revision；聊天试作可写“未建档”，不得占用真实作品编号 |
| 当前节点 | 主模块、必要次模块、当前阶段与本轮交付清单 |
| 交付范围 | scope=prompts/media；只做文字不等于省略图片提示词 |
| 制作输入路线 | 参考驱动、纯文生或未定，记录用户选择或已核验入口条件；不能由scope或图片缺失推断 |
| 输入来源 | 本步实际读取的 PRD/脚本/资产/前段结果及版本 |
| 决策状态 | 用户已确认、用户授权下的工作假设、仍待确认，分别列出 |
| 本步结果 | 文件/章节或完整聊天产物，明确已完成范围 |
| 资产 | CHAR/OUTFIT/SCENE/PROP ID、用途、文字候选或已审实际资产；真实引用才填文件路径 |
| 镜头 | shot_id、叙事或信息作用、计划时长、三要素、起止状态、与前后镜头的联系 |
| 依赖 | 后续哪个节点/镜头使用本步结果，哪些尚依赖实际图片或真实终帧 |
| 检查 | 检查对象、检查者、结论与证据；区分文本/平台适配/视觉/播放/用户选择 |
| 下一步 | 可直接进入的节点、仍缺的必要输入；不以未回答的问题视作同意 |

完整多镜头的提示词包把角色/场景/道具参考图、逐镜首帧图片正文和动态正文分别交接。资产状态分为文字候选、待生成、已审实际图；无图时可以完成计划首帧候选，但实际图像绑定和图生视频就绪状态仍待满足。已有适用资产复用其版本，单节点与明确纯文生请求按用户范围裁剪，不重做无关阶段。

## 镜头三要素与连续性

每个镜头必须让接手者看懂：

1. **相机**：景别、视角/高度、观察方向、固定或运动及其起止。固定镜头也是明确选择，不为了填字段强加运动。
2. **角色或主体**：谁做什么，动作顺序、姿势/朝向、可见表情、视线、台词、与道具的接触。无人镜头记录环境或产品变化，并注明角色不适用。
3. **画面**：前中后景、主体画面位置、可见范围、光线、环境与重点信息。

另记录计划入口/出口与实际入口/出口。画面左/右相对于当前镜头；空间东/西、门/窗、人物身体左右是另一套坐标。运动机位必须说明改变后的画面位置，不能用“保持左右不变”覆盖真实绕拍。

匹配的是情境和因果，不是强求每个镜头首尾像素相同。动作接切、视线接切、反应镜头、空镜、声音先入都可使用；明确观众应理解的关系。连续长镜头跨生成片段时，记录设计镜头与生成片段的对应，不混淆二者。

## 交接完成标准

- **能进入下一节点**：必要创作决定可执行，未确认项不会让下一步建立在相反假设上。剩余非关键项可以带着清楚标签继续。
- **文字可发送**：正文完整、无占位/内部编号/“同上”，图像与动作分工正确；需要参考文件时映射和上传说明真实完整。未选平台可交付通用自然语言版，同时标明尚未核验平台适配。
- **依赖尚未满足**：例如“必须沿用前一段实际终帧”但该图未提供，只给候选/草案和所缺素材，不把它放入已就绪批次。若用户选择改走独立文生视频，明确改路线并复核一致性约束。
- **媒体可用**：必须实际检查文件及播放。首帧通过不等于全段通过；文字通过也不等于媒体通过。

## 修改怎样传播

1. 定位被修改的事实来源和版本；用户明确的新决定优先。
2. 计算语义影响：角色衣装→资产/可见镜头；对白→口播时长/口型/剪辑；场景布局→调度/机位/关键帧；前段真实终帧→连续动作的后段。
3. 列出要复查的产物与可保留的产物。内容变化按项目规则升版，重置相应审查与生成状态，不删除历史。
4. 下游只消费当前有效版本。仅“看起来差不多”的旧图不得默认为新版本证据。

## 平台输入分支

- 支持首帧输入且实际首帧已检查：图承担起点，文字重点控制变化。
- 只能用身份/风格参考：按其用途上传，仍需写清起始构图；身份图不等于第一帧。
- 只有文字输入：完整描述必要身份、空间、起始状态；承认控制能力限制，不给“先重建图片再输入同一工具”的不可执行步骤。
- 要求首帧连续但当前工具不支持：提供换用已核验图生视频路线或调整为可剪辑文生视频镜头两种可执行选择；不能暗中换工具/成本。

## 作品文件映射

沿用 00需求、01设定、02脚本、03分镜CSV、04提示词、05结果、06验收、07连续性、08分段。场面调度、声音和剪辑说明可放相应 Markdown 专节或按需增补文件，不更改旧 CSV 表头，不强迫历史作品补齐全部新字段。

本协议的文字演练结果见项目本轮训练报告；没有媒体实测时，视觉一致性、模型执行精度和平台通过率仍未核验。
