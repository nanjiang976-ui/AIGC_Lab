# aigc-creator（全链路创作总控）｜调用模板与使用方法

这是发给 Codex 的调用模板，用于识别任务和安排节点；不是发给图片或视频模型的生成正文。
新作品可以统一从这个入口开始；在“作品用途”写明类型，总控会结合目标与已有资料选择主类型和当前节点。类型已明确可直达类型模块，只做某一步可直达专业节点，续作不必重新走需求访谈。

## 最少告诉它什么

在 AIGC_Lab 内读取本项目同版本 Skill 源码和配套协议，不混用旧全局安装副本。

最少说清“想做什么”和“这轮先做到哪里”。详细模板中的用途、规格等可逐步补齐；不是开工前必须填满的表单。已有作品就给作品目录或当前版本；新想法可只给一句话。
不需要自己选择全部节点、编资产 ID 或填写 Clip 映射。Codex会从当前需求、设定、脚本、分镜和修改记录整理作品脉络，承接全片风格、人物此刻知道/想要什么、真实图像/声音状态和最新修改；不用每步再填一遍。

作品用途决定类型模块；真人/2D/3D、画风与画幅是表达约束；“本轮先做到”决定当前节点。三者分开，例如“AI剧情与漫剧、2D竖屏、本轮只写剧本”。用途未定时由总控提出判断；混合用途通常一主一次，依据主要目的取舍，不把菜单中的全部类型当成已选择。

## 短口令

> 帮我做这个视频，先整理想法和需求；每步给我调整，再由我调用下一节点。
>
> 接着这个作品往下做，先告诉我当前卡在哪里。
>
> 按当前剧本准备完整角色资产：参考图提示词和人物音色设计、试听文本；这步交完先停。
>
> 结局改成她独自离开；先列出受影响的铺垫、调度和配乐，保留还能用的素材，这轮只改剧本。

## 可复制调用模板

替换【】中的内容后发给 Codex；作品用途选一项，混合用途另说明主次。不清楚的项直接写“未定”，没有材料写“暂无”。删除未选菜单，不必为填满模板补造设定。

```text
请使用 AIGC_Lab 本项目源码中的 $aigc-creator，按当前版本组织这部作品。

作品用途：【AI剧情与漫剧／商业广告／科普解释／主持人口播／纪实与重建／音乐影像／产品演示／视觉艺术／混剪回顾；选一个，未定时请帮我判断】
作品想法：【用几句话说明我想做什么；续作请注明作品目录和当前版本】
主要目的：【希望观众看懂什么、产生什么感受，或者采取什么行动】

已有材料：【暂无／已有需求／已有剧本／已有角色和场景／已有生成结果；附上具体内容或位置】
表现形式：【真人写实／2D／3D等】
画面风格：【具体风格，未定可写未定】
计划规格：【单条还是系列、集数、每集时长、画幅】
声音要求：【对白语言、是否有方言、旁白、BGM；未定可写未定】

必须保留：【已确定的人物、剧情、台词、结局或其他限制】
生成平台：我在 LibTV 中执行；具体模型和入口【已知则填写，未知写未定】。
制作路线：【参考图驱动/纯文生/未定】

本轮先做到：【整理需求／写剧本／准备完整资产／写完整调度／编写Clip／剪辑方案／复盘】
保存方式：【先只在聊天输出／在本项目中为这部作品建立独立目录并保存／保存到已指定作品】
公共库：【本轮不入公共库／有可复用经验时按项目规则处理】

请先说明：
1. 采用哪个主类型模块，以及选择理由。
2. 当前从哪个节点开始。
3. 本轮会交付什么。

只补影响当前步骤的关键缺口，一次问一个。
每个用户节点完成后先停下，供我修改，并给出下一步可复制口令。
Codex本轮只准备文字和提示词，图片、声音和视频由我在LibTV生成。
```

“保存作品”和“进入公共库”分别选择；不入公共库不等于不保存作品。上述通用模板可用于九类用途；没有生成需求的现有素材混剪、真实录屏等任务，按既有材料裁剪，不强制出图或Clip。若使用其他平台，将生成平台一行替换为实际平台和执行方式。

## 已填示例

```text
请使用 AIGC_Lab 本项目源码中的 $aigc-creator，按当前版本组织这部作品。
作品用途：AI剧情与漫剧。
作品想法：两个成年好友雨夜见面，阿宁归还雨伞表达歉意，周川从拒绝到接过雨伞，完成克制和解。
主要目的：让观众感受到人物通过行动修复关系。
已有材料：暂无，这是新作。
表现形式：2D动画。
画面风格：冷色雨夜与暖色路灯，表演自然克制。
计划规格：单条，30秒，9:16。
声音要求：少量中文普通话对白，保留雨声；BGM是否需要由剧情节奏判断。
必须保留：两名主要人物，结尾不拥抱，不用旁白解释和解。
生成平台：我在LibTV执行，具体模型与入口未定。
制作路线：参考图驱动。
本轮先做到：整理创作需求、人物关系和需要确认的剧情问题，先不写完整Clip。
保存方式：只在聊天输出。
公共库：本轮不入公共库。
请先说明主类型模块、当前节点、本轮交付和选择理由。
只补当前关键缺口，一次问一个；这步完成后停下，给下一步口令。
Codex只准备文字，图片、声音和视频由我在LibTV生成。
```

## 会得到什么，怎样继续

会先辨认已有资料与当前阶段，简短说明“主用途模块及理由／当前节点／本轮交付”，读取对应规则后真正执行当前步骤，再给产物、必要假设/未知和下一步。只输出路由标签不算完成创作请求。资料足够就直接开始，不为模板多了一些字段而重新访谈；用途不确定只问影响当前选择的关键问题。

剧情与漫剧通常承接人物因果；其他类型按本类型的实际输入和判据走，例如广告先核对主张依据、纪实先梳理来源、音乐影像先确认曲目/段落、产品演示先核对真实界面、混剪先盘点已有素材。九类操作顺序见项目根README的“按作品类型逐步制作”模块；脱离完整项目时按同版[总控选择规则](routes.md)和类型Skill执行，不依赖不存在的README。

需求确认后说“按上述需求写剧本”；剧本改好后说“按上述剧本准备视觉资产和人物音色”，会后台协同参考图、音色设计和试听文本；只要图时直接说“只做人物、重要道具和场景参考图提示词”。之后可调用“写完整镜头调度，带每Shot声音和BGM提示词”，再转Clip及真实输入连接说明。每步交付后默认停下，便于先修改；只有明确要求连续完成时才继续。

人物新建和转换使用同一四格视图：上排正面/3/4转侧胸像，下排背全身/正面略3/4全身；重要道具每件单独一张。需要固定声音的角色得到独立音色设计和试听文本；每个需配乐Shot有完整可复制的BGM提示词，并说明延续同段、变奏或收束，允许不配乐。音色与BGM由audio承接，不必记住额外Skill名；MV仍按音乐影像类型处理。

同一聊天直接复用当前有效成果；跨聊天由Codex整理含来源版本、剧情前中后、资产/声音真实状态、入口出口和最新修改的短交接包。上游改变先刷新脉络再更新受影响内容：角色改方言会复查声音/对白/口型时长，结局改变会复查铺垫与配乐；无叙事影响的颜色变化不会重做声音。
只做一个节点时，可以转用对应节点的模板，省去整链安排。

下一句不必重复整份开工模板。例如“沿用刚才的需求，只写剧本”；总控沿用已选用途、风格、声音和保持项，再进入相应当前节点。修改用途或主要目标时先重新判断影响，不默默丢掉原限制。

## 重要依赖

参考图驱动需要真实图片时，会先交图片提示词，依赖图片的 Clip 保留草案。
只准备文字不等于改走纯文生；生成、上传、费用和发布沿用已有明确授权。
平台未定仍能创作，专用输入格式和模型执行效果要另行核验。
执行细则见本包 [SKILL.md](../SKILL.md)。
