# 在 AIGC_Lab 中怎样持续迭代

适用于日常图片、视频与漫剧创作。目标是让真实反馈进入下一版，并让适用的方法在下一部作品中被主动找到。完整规则以[持续迭代规范](../spec/持续迭代.md)为准。

## 你每轮需要提供什么

用日常话描述即可：**哪部作品、哪里有问题、想达到什么、哪些不能改、本轮做文字还是媒体**。不需要自己整理 EXP 编号、模板和全部字段，Codex 负责定位当前版本与相关经验。

有实际媒体时，尽量提供对应镜头、时间段或截图，并描述观察；只有文字时，反馈文字、节奏、信息与表达。没有检查到的画面和声音不会记作实际通过。

## 第一次开始一部作品

```text
请使用 $aigc-creator，在 AIGC_Lab 创建一部新作品。
主题是【想表达的内容】，用途是【给谁看、发布在哪里】，目标【时长或张数】。
开工前先检索相关经验，说明采用了什么或为什么没有匹配。
本轮只准备文字和提示词，不调用媒体生成。
```

没有足够信息时每次只补最影响创作的一个问题；已有 PRD、脚本或设定就直接提供，不必重新回答一遍访谈。Agent 提出的角色、风格和细节仍标工作假设，不能冒充你已确认。

## 看完一稿，给具体反馈

优先选一个最关键的改进目标，再写不能改变的内容。例如以下只是反馈格式示例：

```text
继续 WORK-003《先做一小步》。这轮优先让观众知道具体怎么开始用 AI。
保留主题、20 秒和现有角色，只改受影响的镜头、提示词、旁白及后期文字。
先列出实际问题与最小修订范围，保留旧版，修改后再复核。
本轮仍只准备文字和提示词。
```

Codex 会区分你的取舍与客观冲突，定位具体镜头及责任节点，保存旧稿后建立下一版。不是每次都重做整部片；角色没有变化就不重做人设，声音或字幕变更也不自动重画无关画面。

## 一轮结束，怎样留下经验

```text
请对本轮做一次短复盘：实际改了什么、哪些检查有结果、还有哪些未知。
有跨作品复用价值的方法先查重，保留来源、条件和证据，再回写经验索引。
只凭文本能验证的结论限定在文本范围；没有新经验可以零新增。
把下一轮从哪里继续写回作品需求卡。
```

通常不用每轮重新说这段，项目 AGENTS 已将它列为收尾流程。保留该口令，便于在新聊天或检查中要求显示具体证据。日常复盘不会自动修改 Skill、全局规则或长期记忆；需要改 Skill 时另开明确维护任务。

## 下一轮或下一部作品如何复用

```text
继续这部作品的下一版，或按以下新需求开始下一部作品：【新需求】。
先读经验索引和相关来源，核对适用条件，记录采用的经验 ID + 版本。
候选经验只作有标注的试用；不要自动沿用不适用的模型、风格或审美偏好。
动笔前写清这次如何判断有帮助，完成后给出实际结果并回写。
```

需要验证的只是当前改法。例如“观众应能照着做”可以先转换成文本可检查条件：是否有明确输入、预期输出和用户接下来的动作。满足文字条件不证明观众确实学会；真实观看反馈仍要另收集。

## 你怎样检查它有没有真的迭代

| 查看位置 | 应看到什么 |
|---|---|
| 作品 00_创作需求.md | 最新决定、哪些仍是工作假设、下轮起点 |
| 作品 06_修改与验收.md | 开工检索、采用/试用的经验版本、具体反馈、改动与实际效果 |
| 作品的历史目录 | 修改前原稿及对应的审查，不能用新稿覆盖旧依据 |
| [经验索引](经验索引.md) | 当前状态、适用范围、来源/证据和验证日期；允许零新增 |
| 具体实验或复盘记录 | 当初想验证什么、实际如何做、结果支持到哪里、反例与未执行项 |

状态为“候选”时，方法尚待验证；“已在指定范围验证”只在写明的条件内使用。模型/入口或关键条件变化、出现反例时重新核对，必要时转“待复验”或“停用”，历史记录保留。

## 屏幕编辑任务的一个具体方法

WORK-003 第一轮的独立审查提出了一条候选方法，编号 EXP-001 / v001；最新状态以[经验索引](经验索引.md)和[实际记录](2026-10-16_WORK-003_持续迭代闭环.md)为准。

如果一镜要表现删除或替换文字，交接时不要只说“改成这句话”，同时写出四项：

| 项目 | 要说明什么 |
|---|---|
| 起始文本 | 改之前到底是什么 |
| 光标或选区 | 从哪里开始操作，或选中什么 |
| 具体操作 | 按什么、删几次、输入什么；只保留当前选定方案 |
| 目标文本 | 操作后应该得到什么 |

然后核对剧本、分镜、后期、声音及状态表有没有相反的描述。这条方法只处理文本交接；实际生成手部、字形、屏幕跟踪和软件行为仍要各自检查。没有可见文字编辑的新作品，就不要为了复用而加入此流程。

如果你说“不保存”，本轮只在聊天交付；说“不入库”，不写公共经验索引、提示词库或模型库，作品内部资料按本轮保存要求处理。提出具体审美意见，默认只对该作品生效；想以后沿用时明确说“以后同类作品默认这样”。

## 本轮真实案例

本轮已在[WORK-003《先做一小步》](../04_作品项目/WORK-003_先做一小步/00_创作需求.md)执行 v001→v002 两轮真实文字创作：

1. 第一轮开始读到空索引，如实记“无匹配经验”，正常交付第一稿。
2. 独立读稿发现镜4有起始/目标句，但光标前提未交代；保存原稿后提出 EXP-001 候选，没有把原稿说成失败。
3. 你对梗概提出“看完知道具体怎么做”，第二轮开工前读回候选与来源，先写定检验方法。
4. 第二轮写清光标位置和三次退格，独立文字推演得到目标句；同时完善可照抄请求、人的操作与可见完成结果。
5. 先保存第二轮审查和复盘，再把经验更新为“已在指定范围验证”；同作品、文本/流程范围之外没有升级。
