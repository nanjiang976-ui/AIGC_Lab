# 节点交接协议

版本 v006，2026-10-20。本协议在本套件中只维护一份。作品根目录依照 [项目接入](project-integration.md) 定位。用户明确完整 AIGC_Lab 工作区时，验证项目契约后优先读该根 `skills/aigc-creator/references/`；脱离项目时再用当前包安装根/技能元数据找到配套总控。先确认共享文件和当前套件配套，不能把新工作树的叶节点混接到旧全局总控。只安装了叶节点时补齐总控依赖，不猜测绝对路径。

套件身份在各 SKILL.md 的 `metadata.bundle` 与 `metadata.bundle_version` 中；本版为 `aigc-lab` / `1.2.1`。脱离项目时比较叶节点与总控这两个字段；缺失或不同则报告需要完整同步，不把“同名”当“同版”。项目内还可与 `skills/catalog.json` 的 bundle_version 核对。

## 三类职责

| 层 | 决定什么 | 不代替什么 |
|---|---|---|
| 总控 aigc-creator | 当前阶段、模块选择、已有资料、依赖和下一步 | 不把所有节点全文重复一遍 |
| 类型模块 | 此类内容的目的、叙事/信息策略、节点取舍、专用验收 | 不复制共享生成节点，不重问完整需求 |
| 共享节点 | 当前阶段的具体创作判断与交付 | 不擅自重写上游确认的角色、剧情、事实 |

用户只要求某一节点时直接进入该节点，先检查必要输入，缺哪个补哪个。完整 PRD 先体检，不重新访谈；新会话从当前版本/下轮起点恢复。一个主模块即可覆盖大多数任务；广告剧情片等混合请求可加一个有必要的次模块，先声明主目标，冲突取舍由用户目的决定。

## 默认逐步交付

面向用户的文字主链为：**想法/需求→剧本→人物、重要道具与场景参考图提示词→完整镜头调度→Clip**。这是交接顺序，不是一次执行全部节点的授权。

- 默认完成当前节点即停止，用户可以先修改本步结果，再自行调用下一节点；不要在结尾口令之后自动执行下一步。
- 用户明确要求连续完成多个节点或完整提示词包时，执行已授权范围，沿用其预览点、缺项处理和停止条件；后台协同分镜、声音等专业能力属于当前节点的制作过程，不要求用户额外逐个调用。
- 同一聊天直接复用当前有效的确认内容与用户最新修改。上一份交付稿不因“已交付”自动变成“用户已确认”；用户明确要求沿用或继续时承接该稿，未定事项仍保留原状态。
- 剧本交付附人物、重要道具与场景资产清单，标明剧情用途、已定外观/结构、已有参考与待补项，供参考图提示词节点接手。已有适用资产复用；用户指定跳过或只做某一步时按范围处理。

## 每次交接的最小记录

可用 Markdown 表或现有作品文件表达，不强制创建额外数据库。数据有来源就引用源文件/章节，避免维护两份事实。

| 字段 | 内容与判断 |
|---|---|
| 作品与版本 | work_id、revision；聊天试作可写“未建档”，不得占用真实作品编号 |
| 当前节点 | 主模块、必要次模块、当前阶段与本轮交付清单 |
| 交付范围 | scope=prompts/media；只做文字不等于省略图片提示词 |
| 制作输入路线 | 参考驱动、纯文生或未定，记录用户选择或已核验入口条件；不能由scope或图片缺失推断 |
| 输入来源 | 本步实际读取的 PRD/脚本/资产/前段结果及版本 |
| 决策状态 | 用户已确认、用户授权下的工作假设、仍待确认，分别列出 |
| 本步结果 | 文件/章节或完整聊天产物，明确已完成范围 |
| 资产 | CHAR/OUTFIT/SCENE/PROP ID、用途、文字候选或已审实际资产；真实引用才填文件路径 |
| 镜头 | shot_id、叙事或信息作用、计划时长、三要素、起止状态、与前后镜头的联系 |
| Clip | clip_id、生成输入模式、Clip与源Shot的时间区间映射、六区块工作稿与平台发送稿、真实参考用途 |
| 依赖 | 后续哪个节点/镜头使用本步结果，哪些尚依赖实际图片或真实终帧 |
| 检查 | 检查对象、检查者、结论与证据；区分文本/平台适配/视觉/播放/用户选择 |
| 下一步 | 可直接进入的节点、仍缺的必要输入；不以未回答的问题视作同意 |

完整多镜头提示词包分别交接参考资产、完整调度、Clip正文与映射。首帧按实际入口选择：身份参考可直接进入Clip，首帧/首尾帧模式才制作对应静态输入；各路线仍描述起点。资产状态分为文字候选、待生成、已审实际图；所需真实图尚缺时保留草案，不称图生就绪。已有适用资产复用其版本，单节点与明确纯文生请求按用户范围裁剪，不重做无关阶段。

## 用户媒体验收与反馈

2026-10-20用户明确决定：作品图片、视频、声音及成片的实际观看、试听和选择验收由用户在LibTV完成，独立审查Skill已从当前套件移除。Codex继续自检提示词、台词、时间区间、结构、素材名称和引用，并根据用户反馈修改对应创作节点；不新建替代审查节点。

- 用户在LibTV确认可用的素材可直接作为创作依据，记录“用户确认／用户报告”，不要求再上传给Codex复审，也不因Codex未看图而阻止文字下游。用户只反馈部分状态时，仅承接已反馈部分，其余保持未知。
- 原“已审实际图／已检查结果”在当前流程指用户已观看确认的真实素材；用户反馈与Codex文字自检分别记录。不得把用户报告改写成Codex已目视或已播放，也不得把尚未反馈的媒体标为用户认可。
- 真实文件、平台图片标签或项目节点仍需真实存在。用户自行在LibTV上传绑定时，可直接记录其提供的完整素材名称与实际标签；尚无标签时交绑定计划，保持待绑定，不虚构路径和编号。实际工具生成需要的素材身份是技术输入，不是新增的审查关卡。
- 用户自行观看后，可直接反馈“已选用”“末尾右手已放在桌西侧”或具体问题；按反馈进入视频提示词、调度、声音或剪辑节点修改。无需默认回传整套图片、视频或声音。
- 本轮仅文字时完整交付所需草案；素材未生成不改变已授权的文字范围。媒体已生成但用户尚未反馈时，记录“待用户验收”，不代替用户给出播放质量结论。

退役范围、原包备份及行为检查见[审查节点移除记录](review-removal-validation.md)。

## 面向用户的结尾衔接

每个节点面向用户交付的最后一段使用加粗文字，写明**下一节点或最近可执行动作、携带本轮哪些具体成果、怎样继续**。给一句可直接发给 Codex 的衔接口令，放在图片/视频模型正文之外；实际输出须填入当前成果，不能留下占位模板。

- 同一聊天继续时直接复用已有内容，只补本步新增资料；跨聊天时点名需粘贴的正文、版本与真实文件。例如携带“刚才修正版的钥匙交接正文及6秒目标”，不泛称“相关资料”。
- 按当前目标、实际输入和依赖选择下一步。下一动作确需真实图片或实际媒体才能执行时，先指向用户在LibTV生成、确认或补充实际素材信息；仅文字的下游可在用户调用后继续完成草案，同时保留未满足的真实素材依赖。缺实际视频时不宣称已完成媒体审查，所缺素材及草案状态一起写清。
- 用户已授权连续完成多个普通节点时直接继续，最终交付时再给结尾衔接，不让用户逐站重述或重复批准。下一步提示本身不增加生成、费用、保存、安装或发布授权。
- 当前节点完成后默认停下，写明可以先修改本步结果及下一节点口令；只有前述明确多节点授权才继续。用户明确到此结束时写“本轮完成，暂无需进入的下一节点”，不强行延长流程。

剧本交付的例子：**本轮剧本已交付，可以先修改。下一节点：人物、重要道具与场景参考图提示词。继续说“按刚才的剧本和资产清单写参考图提示词，沿用两姐妹、外套右口袋、戒指和客厅设定，仅聊天”；本聊天直接复用当前稿与已确认项，本轮先停在剧本。**

完整调度已就绪的例子：**下一节点：aigc-video-prompts。继续说“把上述完整调度转成 LibTV Clip，沿用人物、衣装与台词，仅聊天”；本聊天直接复用刚才的逐镜调度和锁定项，实际参考图未提供的部分保持草案。**

参考图提示词交付的例子：**本轮人物、戒指与客厅参考图提示词已交付，可以先修改。下一节点：完整镜头调度。继续说“沿用刚才的剧本、资产清单和参考图设定，写完整镜头调度，仅聊天”；本聊天直接复用这些内容。若已在LibTV生成并确认素材可用，可一起反馈选用结果及实际素材标签；尚未生成时保留素材依赖，仍可先写调度草案。**

这条规则统一维护于本节。各节点保留专业职责和既有交接资料，不再维护另一套固定流水线。修订的真实行为范围见[结尾衔接验证](next-step-validation.md)。

## 镜头三要素与连续性

每个镜头必须让接手者看懂：

1. **相机**：景别、视角/高度、观察方向、固定或运动及其起止。固定镜头也是明确选择，不为了填字段强加运动。
2. **角色或主体**：谁做什么，动作顺序、姿势/朝向、可见表情、视线、台词、与道具的接触。无人镜头记录环境或产品变化，并注明角色不适用。
3. **画面**：前中后景、主体画面位置、可见范围、光线、环境与重点信息。

另记录计划入口/出口与实际入口/出口。画面左/右相对于当前镜头；空间东/西、门/窗、人物身体左右是另一套坐标。运动机位必须说明改变后的画面位置，不能用“保持左右不变”覆盖真实绕拍。

匹配的是情境和因果，不是强求每个镜头首尾像素相同。动作接切、视线接切、反应镜头、空镜、声音先入都可使用；明确观众应理解的关系。连续长镜头跨生成片段时，记录设计镜头与生成片段的对应，不混淆二者。

## 交接完成标准

- **能进入下一节点**：必要创作决定可执行，未确认项不会让下一步建立在相反假设上。剩余非关键项可以带着清楚标签继续。
- **文字可发送**：正文完整、无占位/内部编号/“同上”，图像与动作分工正确；需要参考文件时映射和上传说明真实完整。未选平台可交付通用自然语言版，同时标明尚未核验平台适配。
- **依赖尚未满足**：例如“必须沿用前一段实际终帧”但该图未提供，只给候选/草案和所缺素材，不把它放入已就绪批次。若用户选择改走独立文生视频，明确改路线并复核一致性约束。
- **媒体可用**：由用户在LibTV实际观看或试听并反馈确认；记录用户确认范围与未确认项，Codex无需重复审图或播放。文字自检与生成成功均不自动代表用户已验收。

## 修改怎样传播

1. 定位被修改的事实来源和版本；用户明确的新决定优先。
2. 计算语义影响：角色衣装→资产/可见镜头；对白→口播时长/口型/剪辑；场景布局→调度/机位/关键帧；前段真实终帧→连续动作的后段。
3. 列出要复查的产物与可保留的产物。内容变化按项目规则升版，重置相应审查与生成状态，不删除历史。
4. 下游只消费当前有效版本。仅“看起来差不多”的旧图不得默认为新版本证据。

## 平台输入分支

- 支持首帧输入且实际首帧已检查：图承担起点，文字重点控制变化。
- 只能用身份/风格参考：按其用途上传，仍需写清起始构图；身份图不等于第一帧。
- 只有文字输入：完整描述必要身份、空间、起始状态；承认控制能力限制，不给“先重建图片再输入同一工具”的不可执行步骤。
- 要求首帧连续但当前工具不支持：提供换用已核验图生视频路线或调整为可剪辑文生视频镜头两种可执行选择；不能暗中换工具/成本。

## 作品文件映射

沿用 00需求、01设定、02脚本、03分镜CSV、04提示词、05结果、06验收、07连续性、08分段。场面调度、声音和剪辑说明可放相应 Markdown 专节或按需增补文件，不更改旧 CSV 表头，不强迫历史作品补齐全部新字段。新Clip流程在project.json选择prompt_layout=clips，以clips_file引用当前版本的Clip—Shot映射，项目字段见spec/clip-contract.md；旧格式缺省per_shot。完整包与最终发送版分开，不把内部资产ID或来源说明复制到模型正文。

本协议的文字演练结果见项目本轮训练报告；没有媒体实测时，视觉一致性、模型执行精度和平台通过率仍未核验。
