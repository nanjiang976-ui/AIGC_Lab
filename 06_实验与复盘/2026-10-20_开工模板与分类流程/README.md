2026-10-20。任务为更新总控开工模板、核对当前入口的实际响应与下游衔接，并将用户选中的剧情漫剧八步及其他八类制作顺序写入根README。范围、假设和保持项见[实施计划](../../spec/plans/2026-10-20-通用开工模板与分类制作流程.md)。

## 基线与本次改动

改前为`9653505d0a0fc64d75e3c52e928df5d1ddc066bd` / 1.4.0。旧版已经有9类用途选择与节点协作，不能把指南字段不完整说成后端断开。旧模板没有单列“作品用途、主要目的、表现形式、声音要求”，README也没有逐类的可操作顺序。本次维护唯一总控usage，补开工的主类型/当前节点/本轮交付说明，保留既有机器ID、路由脚本与节点职责。

[旧版同题实际执行](基线执行_1.4.0.md)只读取该Git提交的1.4.0源码，已经能选择narrative与prd、整理需求/人物关系并一次只问一个问题。改前未出现被人为制造的连接失败；新版同题与其他八类用于核对新模板及具体交接，而非证明旧版没有这些能力。

README新增剧情八步完整操作模块，保留用户选中的修改示例、继续口令、资产与声音生成反馈、按需首尾帧、实际终态承接和剪辑复盘；另外八类各有独立标题、折叠步骤表和短开工口令。通用模板不在README重复维护，统一链接总控指南。

## “后端有反应”的三个层次

1. **入口识别**：本地只读路由找到creator、类型线索与真实usage路径。它不运行创作，不连接LibTV。
2. **实际文字执行与承接**：执行者读取同版总控、相关类型与当前节点，产生本轮实际内容，再接收下一条继续请求，复用前一答的事实与保持项。必须保存原输入/输出；只写“该调用哪个节点”不足以通过。
3. **平台与媒体执行**：登录账号、素材绑定、图片/音频/视频生成、播放或用户效果验收。本轮未执行，不从前两层推导连接成功。

## 请求与只读识别

[九类实际请求](九类实际请求.json)是为本轮维护构造的代表性中文请求，每类有完整开工字段和下一条继续请求；不是九部用户已存在作品。文中教学规则、产品外观或素材观察仅是演练输入，未声明真实外部素材已被执行者观看。

[调用识别检查](调用识别检查.json)：9个已填模板均命中显式creator，且各自仅保留预期的主用途线索。未填菜单仍命中creator、出现9个词面候选；这不是9类都被选中，当前总控规则要求回读未定/菜单状态后再判断或问一个关键问题。原脚本行为如实保留，没有用关键词识别冒充完整语义判断。

现有调用回归32项和包回归40项通过，21个包与21个Skill格式检查通过。未修改脚本逻辑、项目schema、作品状态或全局安装副本。

## 九类实际双轮结果

原始输入与完整答复分别保存在[A组：剧情、广告、科普](实际执行_A_剧情广告科普.md)、[B组：口播、纪实、音乐](实际执行_B_口播纪实音乐.md)、[C组：产品演示、视觉艺术、混剪及空白模板](实际执行_C_演示视觉混剪.md)。逐字检查确认九条request与九条continuation都保留在对应记录中。

| 用途 | 第一轮实际交付 → 下一轮实际交付 | 保持项或有意省略 |
|---|---|---|
| 剧情与漫剧 | 人物需求/关系 → 30秒剧本与资产清单 | 两位好友、不拥抱、无新增过错；没有直接跳到Clip |
| 商业广告 | brief/主张与依据 → 15秒三镜脚本 | 固定杯形与文案；没有新增性能承诺 |
| 科普解释 | 教学依据/图像映射 → 24秒解释脚本 | 阈值与卡片标签继承，新卡仍待测 |
| 主持人口播 | 需求及可讲述稿 → 音色、试听稿与重音停顿 | 第二轮逐字承接主稿；声线和时长仍待试听 |
| 纪实与重建 | 来源事实整理 → 30秒结构及素材计划 | 未回答的访谈归属继续待绑定；不编真实源入出点或重建 |
| 音乐影像 | 视觉节奏谱 → 24秒单镜三段分镜 | 原曲与三段结构保留，不新增BGM或角色；尺寸单位问题见下 |
| 产品演示 | 操作目标/脚本 → 18秒录屏分镜及高亮解说 | 原按钮和步骤不改，不生成替代真实UI |
| 视觉艺术 | 单环视觉规则/周期 → 8秒六区块八STYLE Clip草案 | 纯文生、静音、无人物；平台和循环播放未执行 |
| 混剪回顾 | 用户观察清单/结构 → 15秒剪辑时间轴 | 4+6+5秒、1倍速、零重叠、原声跟随源区间；不生成新画面 |

独立审查逐项阅读实际正文后，未发现阻断本次维护的问题。空白完整模板也实际执行了一次：主类型保持未定，进入需求节点，只问一句作品想法，未执行九类菜单。

### 保留的问题与验证限度

- 音乐第一轮将方框最大边长写成画面宽度58%，在16:9下会超出画面高度。第二轮明确改为画面高度26%–58%，并把修正单位传入分镜、连接说明与继续口令。原始第一答未改写，不能说首轮所有内容都无缺陷；该例支持“下游发现并显式修正”，不单独形成新通用Skill规则。
- C组初次读取输入JSON时，因投影方式错误短暂暴露部分`expected_module`。该偏差保留在文件开头；其完整输出可作为实际执行证据，不能称完全盲测，也不用于统计可靠性结论。
- 9个首轮与9个续接加空白模板单轮，共19次新版文字答复。另有1次旧版同题基线；这些不是19次平台运行或19部作品。

## 验证边界与复盘

每类只观察本轮代表请求的两次实际文字执行，不宣称穷举所有自然语言、已自动执行整部影片或建立统计可靠性。9类都可以由总控进入，但类型模块与当前工作节点要分别核对，不能要求所有类型都做剧情、人物参考图、音色或Clip。

使用skill-creator和self-improvement做限定复查；没有可直接适用的已验证EXP，公共经验零新增。本文只记录这次模板与流程维护，不修改第三方/系统Skill、长期记忆、LibTV派生包或用户已有作品。
