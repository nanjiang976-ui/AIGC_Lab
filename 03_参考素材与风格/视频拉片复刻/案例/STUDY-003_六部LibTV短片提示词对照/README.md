## 多Shot究竟一次生成还是拆开

**Shot是设计镜头，Clip是按一次独立生成任务组织的片段单元。** 一条写了多个Shot的Clip，当前设计意图就是把这些镜头在一次请求里生成；若改为每Shot单独生成，就应编成多条独立Clip，再剪辑。同一计划Clip可以重试或保留多个候选，计划Clip数不等于含重试的实际请求总数。

以下为原创结构示意，不是平台可发送正文，也不代表已选择实际输入：

| 同一12秒、3镜设计 | 一次生成方案 | 分别生成方案 |
|---|---|---|
| 输入组织 | Clip 01内写Shot 1/2/3 | Clip 01、02、03分别对应一个Shot |
| 片内时钟 | 0–4、4–8、8–12秒 | 每条都从0秒开始，分别0–4秒 |
| 计划首次请求次数（不含重试） | 1次 | 3次 |
| 切镜执行 | 要求模型在该视频内部切镜 | 后期把三个视频接起来 |
| 主要取舍 | 同段动作/声音可在一起组织，需核对每镜是否执行 | 便于单镜重做和分别控制参考，需维护跨段状态/声音 |

不是所有时刻变化都需要切镜：李白MV的5秒样本和《半面罪》的15秒样本都明确为连续镜头，却分别有2个和5个时间段。另一方面，单个长Shot若超过一次能力而分两次生成，仍可保留同一Shot身份；实际接缝是否自然需看片段，不因编号相同就成为真正无缝长镜。

**本次建议采用混合分组，尚未设为项目默认新规则：**

- 同一时空、连续表演/对白、共享参考与声音、前后镜头形成一个紧密节拍单元，且当前入口能承载：可先考虑多Shot一Clip。
- 关键特写或动作需要独立重做、场景/角色/参考体系明显变化、对白或复杂事件挤在一起、必须精确踩音乐点，或入口缺相应控制：优先比较拆成独立Clip的方案。
- 成片时长和Shot数本身不足以决定分组；还要考虑画面信息可读性、输入角色、声音消费、动作难点与返工范围。九镜/16秒是该例的计划，不是所有任务的建议值。
- 拆分后每条仍须自足、写完整本场衣装/空间/起点和对应素材，不能只把原包中的“Shot 2”一句单独粘贴。连续音乐可以用一条实际音轨跨多个Clip，不因拆画面就重新生成不同BGM。
