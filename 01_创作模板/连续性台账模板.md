# 连续性台账模板

这是空白工作模板，不是已确认的作品设定或实际画面证据。复制到目标作品目录的 `07_连续性台账.md` 后填写，与 `01_故事与角色设定.md`、`03_分镜表.csv`、`06_修改与验收.md` 和 `08_分段与衔接.md` 配合使用。图片系列也可以使用本台账；单图不适用的时间、声音和段间字段写明原因。

本台账记录“哪些必须一致、当前发生了什么、下一段从哪里接”。设定正文仍以 `01_故事与角色设定.md` 为准；发现冲突先解决，不把两个版本混用。它不增加或更改现有 CSV 字段，也不取代 `project.json` 的作品状态。

## 1. 本轮位置与决定来源

| 字段 | 填写内容 |
|---|---|
| 作品 ID / 当前版本 | {{WORK-编号 / v编号；与 project.json 一致}} |
| 本轮范围 | {{prompts / media}} |
| 当前段落 / 镜头 | {{分镜中的 shot_id}} |
| 已完成的文字材料 | {{真实文件与范围；未完成则写未完成}} |
| 已生成且已检查的媒体 | {{真实文件与检查记录；没有则写无}} |
| 用户最新明确决定 | {{决定内容、对话日期或作品内决定记录位置}} |
| 下一步 | {{一项具体动作；需要什么输入}} |
| 阻碍与待确认 | {{只记会改变剧情、外观或生成计划的事项；没有则写无}} |

讨论中的提议先记为“候选”；用户明确选择，或用户已授权 Agent 在该范围内决定并实际作出取舍后，才记为“锁定”。锁定须记录依据与决定者，不把沉默、默认模板或 Agent 偏好写成用户确认。

| 决定 ID | 对象与内容 | 状态：候选 / 待确认 / 锁定 / 已替换 | 决定者与依据 | 生效版本 / 镜头 | 替换关系 |
|---|---|---|---|---|---|
| {{DEC-编号}} | {{具体决定}} | {{状态}} | {{用户明确选择或授权内 Agent 决定}} | {{版本和范围}} | {{无或旧决定 ID}} |

“锁定”仅表示当前创作依据稳定，不表示已生成、效果满意或媒体审查通过。已替换的决定保留记录，不再用于当前发送版。

## 2. 固定 ID 与不变项

角色用 `CHAR-001`，服装用 `OUTFIT-001`，场景用 `SCENE-001`，道具用 `PROP-001`。同一对象跨镜头沿用同一 ID；换装新增服装 ID，人物不换 ID。编号只是项目索引，发给模型的提示词还必须展开该 ID 对应的明确特征，不能假定模型认识编号。

| 对象 ID | 设定正文位置 | 当前固定特征 | 必须保持的辨识点 | 允许变化与触发条件 | 决定状态 / 来源 |
|---|---|---|---|---|---|
| {{CHAR-编号}} | {{设定位置}} | {{脸型、年龄段、发型、身形等}} | {{少量重要特征}} | {{情绪、受伤等及剧情依据}} | {{锁定或待确认；决定 ID}} |
| {{OUTFIT-编号}} | {{设定位置}} | {{颜色、版型、材质、配件位置}} | {{领口、袖口、标记等}} | {{湿、脏、破损或换装及触发镜头}} | {{状态与依据}} |
| {{SCENE-编号}} | {{设定位置}} | {{门窗、物件布局、尺度关系}} | {{关键地标与朝向}} | {{时间、天气、灯光变化及依据}} | {{状态与依据}} |
| {{PROP-编号}} | {{设定位置}} | {{形状、尺寸、颜色、材质}} | {{不可混淆的细节}} | {{开合、损坏、移交等及依据}} | {{状态与依据}} |

无对应对象则删去占位行并写“无”；不要为了填满表格新增角色或道具。未知内容写“待确认”，不把它伪装成固定项。

## 3. 参考资产登记与选择

先登记实际资产，再决定其作用；只有确实存在且可用的文件，才能写入 CSV 的 `reference_files` 或本次实际发送清单。文件使用作品目录内的相对路径，不用绝对路径、`../` 越界路径、符号链接或 Windows 重解析点。公共库资产需先复制进作品并保留来源。

| 资产 ID | 实际相对路径 | 文件存在且非空的检查结果 / 日期 | 来源与允许用途 | 对应对象 ID | 参考作用 | 当前选择与依据 |
|---|---|---|---|---|---|---|
| {{REF-编号}} | {{真实路径；尚无资产则此表不建实物行}} | {{已检查 / 未检查}} | {{来源、用途限制}} | {{对象 ID}} | {{身份 / 服装 / 空间 / 风格 / 入口状态}} | {{候选 / 当前采用 / 历史；决定记录}} |

| 尚需的资产 | 所需视角或信息 | 用途 | 获取方式与授权情况 | 当前状态 |
|---|---|---|---|---|
| {{例如角色正面与侧面}} | {{需要看清的特征}} | {{解决哪项连续性问题}} | {{用户提供 / 待授权生成等}} | {{待获取}} |

待获取资产只写需求，不先虚构文件路径。生成后的尾帧属于状态参考；角色母版、服装母版、场景布局参考承担稳定身份或结构的作用，两者不能互相替代。

## 4. 母版与首段基准

| 项目 | 记录 |
|---|---|
| 当前角色 / 服装 / 场景基准 | {{已选择的资产 ID 或明确无资产}} |
| 代表性首段 shot_id / clip_id | {{分段表中的编号；未生成则写计划}} |
| 首段实际文件 | {{实际相对路径；未生成写无}} |
| 与固定设定的检查 | {{脸、服装、布局、光色、动作、声音逐项结论与证据}} |
| 母版是否可作为后续依据 | {{待检查 / 可用 / 不可用；具体范围}} |
| 审查身份和日期 | {{实际审查者和日期；未执行写未执行}} |
| 用户审美认可 | {{用户明确认可及依据 / 尚无用户认可记录}} |

媒体阶段先生成并检查一个有代表性的段落，在现有授权范围内认可其作为技术基准后再扩展；不强制把每轮内部审查变成新的许可请求。没有实际文件时，母版可保持“计划”，C-03/C-04 仍为 `NOT_RUN`。

不要只把上一段尾帧一段段传下去。每个片段都要回看稳定母版与固定设定；关键换景、换装、明显变形或漂移时重新核对。上一段尾帧与母版冲突时先修正或更换可用切点，不能把错误脸型、服装或道具变成新的标准。

## 5. 逐镜头入口与出口状态

每个 shot_id 复制一张状态卡。入口是“这一段开始时已经成立的事实”，出口是“这一段结束后下一段可以继承的事实”。镜头时长与实际生成片段另记在 `08_分段与衔接.md` 的分段表。

### {{shot_id}} 状态卡

| 项目 | 计划入口 | 计划出口 | 实际出口及证据（生成后填） |
|---|---|---|---|
| 时间、地点、剧情进度 | {{时空与已发生事件}} | {{段末已完成事件}} | {{真实观察；未生成写未执行}} |
| 角色 / 服装 ID | {{角色与服装映射}} | {{是否变化及触发动作}} | {{真实状态}} |
| 身体姿势与动作阶段 | {{站坐、左右脚、手臂、正在做什么}} | {{动作完成到哪一步}} | {{终帧或可用切点的状态}} |
| 道具位置与持有 | {{PROP-ID、谁的哪只手、朝向、开合}} | {{移交或放置后的状态}} | {{真实持有者与位置}} |
| 视线、面向与运动方向 | {{看向谁；画面左/右；朝内/外}} | {{段末朝向与运动趋势}} | {{真实方向}} |
| 空间关系与镜头轴线 | {{人、门、桌的位置；镜头位于动作轴哪侧}} | {{轴线是否跨越及观众如何理解}} | {{真实布局与镜头侧}} |
| 景别、机位与运动 | {{高度、距离、镜头是否运动}} | {{段末机位和运动趋势}} | {{可用于下一段的机位}} |
| 光线、天气与色彩 | {{主光方向、时间、冷暖、曝光基调}} | {{是否有剧情驱动的变化}} | {{真实光色}} |
| 声音与对白进度 | {{谁说到哪句、环境声、音乐、是否口型同步}} | {{句子是否结束；待延续声音}} | {{真实音轨和断句；无声音写无}} |
| 字幕或画面文字 | {{如后期添加则明确}} | {{字幕是否跨段}} | {{真实呈现；未制作写未执行}} |

- 本段固定约束来源：{{对象 ID、决定 ID、母版资产 ID}}。
- 计划采用的下一段衔接：{{下一 shot_id；切点与原因}}。
- 不适用项及原因：{{例如纯图片无动作出口}}。

## 6. 前段实际终帧与差异处理

| 前段 shot_id / clip_id | 计划出口 | 实际可用出口 | 取帧文件与时间码 | 差异影响 | 处理与依据 | 后段是否可继续 |
|---|---|---|---|---|---|---|
| {{编号}} | {{计划状态}} | {{实际检查状态}} | {{真实帧路径；原视频时间码}} | {{身份 / 动作 / 空间 / 光色 / 声音}} | {{返工 / 改切点 / 有依据地修改后段}} | {{待复查 / 可继续；检查证据}} |

可用出口不一定是视频文件的最后一帧。若末尾已经变形，可选择前方干净切点并调整实际保留时长；这是一项剪辑变更，要重新核算总时长和后段入口。实际结果偏离用户锁定剧情时，不能为了拼接方便自行改剧情。

## 7. 变更影响与依赖重验

| 变更来源 | 受影响 shot_id / clip_id | 影响原因 | 提示词需更新 | 媒体需重生成或复查 | 当前处理状态与证据 |
|---|---|---|---|---|---|
| {{角色/服装/场景母版，前段出口，剧情决定等}} | {{具体编号}} | {{依赖了哪项旧信息}} | {{是/否及理由}} | {{动作与范围，不默认全部重做}} | {{未执行 / 已处理；证据}} |

母版变化要检查所有引用该母版的段落；前段出口变化至少检查所有依赖它的后段，直到依赖被重新确认或在独立场景基准处明确重置。不要只修上一段却继续使用后段的旧通过记录。

修改已准备或已验收的具体内容时，按项目规则保留旧版本、递增作品 revision，回到 `DRAFT`，重置对应生成与审查状态。历史媒体不删除，也不能直接充当新版本证据。

## 8. 下次恢复与验收

重新进入作品时按顺序读取：`project.json` 当前版本 → 本台账的最新决定和下一步 → 当前设定 → 分镜与分段表 → 实际发送记录和媒体审查。核对引用文件确实存在，确认没有未处理的上游变更；缺失素材写“缺失”，不根据旧路径声称已拥有素材。

- 文字检查：对象 ID、固定项、状态变化、入口出口、参考选择与提示词是否一致；写明“提示词与设定一致性检查”。
- 媒体检查：逐段对照母版，播放相邻段落及拼接处；检查脸部、服装、道具、动作、视线、空间、光色、声音与实际时长。
- 记录范围、版本、实际审查身份、结论和真实证据到 `06_修改与验收.md`。只有文字时，实际画面一致性 C-03 与媒体可用性 C-04 均为 `NOT_RUN`。
- 本模板帮助降低不一致和返工，不能保证生成模型始终保持同一人物或无缝长镜头。不能由模板填写完成推导媒体 `PASS`。
